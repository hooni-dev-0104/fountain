# 관리자 콘텐츠 검색

소유자 또는 콘텐츠 검색 권한을 명시적으로 받은 관리자는 설정에서 한 워크스페이스의 페이지·데이터베이스·행을 ID·제목·본문으로 검색할 수 있습니다. 일반 문서 접근 권한과 분리된 관리 기능이며, 기존 역할에는 새 권한을 자동 추가하지 않습니다.

| 권한 | 허용하는 작업 |
| --- | --- |
| 콘텐츠 검색 | 검색 결과·공유 범위·접근자·작성 이력 조회 |
| 콘텐츠 CSV 내보내기 | 검색 메타데이터와 접근자 전체 목록 내보내기 |
| 콘텐츠 권한 관리 | 현재 공유 설정 검토, 개별 접근 철회, 그룹 직접 권한 제거, 공유 설정 변경 |
| 콘텐츠 게시 관리 | 페이지 사이트와 데이터베이스 폼의 게시 해제 |
| 휴지통 페이지 복원 | 선택 페이지의 공유 검토와 원래 위치·개인 페이지 복원 |

내보내기·권한 관리·게시 관리·복원에는 콘텐츠 검색 권한도 필요합니다. 역할 지정만으로 일반 페이지·DB API의 접근 권한이 확대되지는 않습니다.

검색은 문자열과 따옴표 구문, 유형, 휴지통 여부, 생성자·최근 편집자와 시각, 공유 범위·접근자·위치를 지원합니다. 본문은 비공개 청크 색인에서 검색하며 클라우드 앱에는 메타데이터와 짧은 발췌를 전달합니다. 검색 중 내용이나 권한이 바뀌면 페이지 커서를 재사용할 수 없으므로 다시 검색해야 합니다.

생성자와 최근 편집자는 서버가 확인한 실행자를 기준으로 기록합니다. 기존 자료는 확인 가능한 과거 기록이 없어 알 수 없음으로 표시합니다. 문서 소유자를 생성자로 추정하지 않으며 일반 JSON 가져오기로 역사적 작성자를 지정할 수 없습니다. 전체 백업·복원은 작성·편집·관리 이력을 보존하고 검색 캐시와 커서 비밀값을 다시 만듭니다.

공유 범위는 실제 접근 권한으로 계산합니다. 현재 게시 사이트에는 로그인이 필요하므로 게시 상태만으로 익명 웹 공개라고 표시하지 않습니다. 폼 입력 공개와 DB 본문 공개도 구분합니다. 공유 변경은 화면의 검토 revision을 확인한 뒤 적용하고, 상속 권한 철회 시 다른 멤버의 기존 상속은 유지합니다.

CSV는 한 번에 전체 파일을 메모리에 모으지 않고 전달하며 마지막 종료 시점까지 세션·역할·원본 변경을 검사합니다. 중간에 권한이 철회되거나 내보내기가 금지되면 정상 완료로 처리하지 않습니다. 직접 파일 쓰기를 지원하지 않는 브라우저의 대체 다운로드는 32MiB, 현재 네이티브 저장 브리지는 8MiB 제한이 남아 있습니다.

검색 추가 단계에서는 PostgreSQL 연결을 포함한 Python 672개 검사와 JavaScript 68개 스크립트가 통과했습니다. 해당 검색 소스는 API 22의 48개 파일과 일치했습니다. 격리된 실제 Auth·Edge·DB 검사, 설치된 Chrome의 8개 흐름, 작성 이력을 포함한 실제 백업·복원과 v2 백업 스냅샷·취소를 확인했습니다. v2의 전체 Storage 파일 생성은 이번 변경에서 다시 실행하지 않았습니다.

앱의 CSV 전송은 데이터와 별도로 완료·실패 기록을 확인합니다. 실제 권한 철회와 내보내기 금지에서 오류 기록과 정상 연결 종료를 각각 3.6초·2.0초에 받았고 파일 저장을 완료하지 않았습니다. 기존 raw CSV API는 유지하지만, Supabase 경로에서 전송 오류의 조기 종료가 관찰되지 않은 사례가 있어 앱은 명시적 완료 확인 형식을 사용합니다.

새 macOS·Windows·iOS·Android 설치물 4종의 빌드·서명·아카이브·전체 공개 자산과 실제 비밀값 미포함을 검사했습니다. 이번 설치물의 앱 실행·실기기·다섯 플랫폼 인증 여정은 수행하지 않았습니다. TypeScript 정적 컴파일러는 추가하지 않았으며 실행 검사를 정적 타입 검사 완료로 표시하지 않습니다. 시험용 계정·세션·자료는 삭제했고 시험 함수는 항상 404를 반환합니다.

별도 보존 자료의 복원·영구 삭제·법적 보류 연계, 조직의 여러 워크스페이스 검색, 유료 원본 화면 전체 비교는 남은 요구입니다. 이 구현을 Notion 전체 유료 기능 또는 전체 관리자 기능 완료로 표시하지 않습니다. 근거는 [구현·검증 기록](research/admin-content-evidence.json)에 구분했습니다.

## 휴지통 페이지 복원

설정의 콘텐츠 검색에서 휴지통의 페이지를 선택하면 현재 공유 범위와 원래 위치를 검토할 수 있습니다. 소유자와 검색·복원 권한을 명시적으로 받은 관리자만 실행합니다. 기존 사용자 지정 역할에 복원 권한을 자동 추가하지 않습니다.

- **내 비공개 페이지로 복원**: 선택 페이지의 소유자가 실행자로 바뀝니다. 상위 페이지·팀스페이스 연결과 직접 공유·상속을 제거하므로 실행자는 복원한 뒤 본문에 접근할 수 있습니다. 워크스페이스 소유자의 관리 접근은 유지합니다.
- **원래 위치로 복원**: 현재의 소유자·공유 설정을 유지합니다. 상위 경로가 누락·삭제·비활성·순환 상태이거나 잘못된 위키 위치이면 적용하지 않습니다.

두 방식 모두 선택한 페이지의 모든 사이트 게시를 끕니다. 자식 페이지의 독립 공유·게시·휴지통 상태는 바꾸지 않습니다. 본문·버전·댓글·공동편집 epoch와 작성자·편집자 이력은 유지하고 관리 실행자만 기록합니다. 검토 이후 자료·권한이 바뀌면 다시 검토해야 합니다. 잠긴 페이지는 복원할 수 없습니다.

공개 웹과 Supabase API 24에 반영했습니다. 실제 Auth/Edge HTTP 7개 그룹과 실제 클라우드 Chrome 10개 그룹을 검사했고, 최종 위치 필터 보완 후 관련 Python 69개 검사도 통과했습니다. 별도 보존 저장소·영구 삭제·법적 보류는 아직 구현 중이며 이번 복원에 포함하지 않습니다. [복원 검증 기록](research/admin-trash-restore-evidence.json)에 코드·SQL·실제 인증·빌드의 범위를 구분했습니다.
