# 관리자 역할

관리 역할은 일반 멤버의 문서·데이터베이스 접근 권한과 별도로 지정합니다. 소유자가 되지 않고도 선택한 관리 작업을 할 수 있습니다. 현재 구현은 한 워크스페이스 안의 사용자 정의 역할입니다.

소유자는 **설정 → 관리 역할**에서 역할을 만들고, 개인별로 여러 역할을 지정하거나 해제합니다. 조회와 관리는 별도로 선택하며 멤버 관리에는 멤버 조회, 그룹 멤버 관리에는 그룹 조회도 함께 선택해야 합니다. 기존 멤버에게 자동으로 역할을 부여하지 않습니다.

| 권한 | 허용하는 작업 |
| --- | --- |
| 감사 로그 조회 | 워크스페이스 감사 기록 조회 |
| 워크스페이스 분석 조회 | 기존 활동·사용량 집계 조회 |
| 멤버 조회 | 멤버 목록과 공개 프로필 조회 |
| 멤버 관리 | 일반 멤버·게스트 등록, 변경, 제거 |
| 그룹 조회 | 그룹 목록과 구성원 ID 조회 |
| 기존 그룹 멤버 관리 | 기존 그룹의 구성원 변경 |
| 콘텐츠 검색 | 한 워크스페이스의 콘텐츠·공유·작성 이력 조회 |
| 콘텐츠 CSV 내보내기 | 검색 메타데이터·접근자 전체 내보내기 |
| 콘텐츠 권한 관리 | 공유 설정 검토·변경·접근 철회 |
| 콘텐츠 게시 관리 | 페이지 사이트·데이터베이스 폼 게시 해제 |
| 휴지통 페이지 복원 | 선택 페이지의 공유 검토·원래 위치 또는 개인 페이지 복원 |

관리 역할을 받은 멤버는 **설정 → 위임된 관리 설정**에서 허용된 화면을 엽니다. 멤버 조회 없이 그룹 조회·관리를 받은 경우 이름 대신 ID로 그룹 구성을 확인합니다. 소유자·멤버십 관리자 계정 관리와 그룹 생성·삭제는 이 위임에 포함하지 않습니다.

활성 일반 멤버와 멤버십 관리자에게 개인별로 지정할 수 있습니다. 게스트·비활성 멤버·소유자는 지정 대상이 아닙니다. 여러 역할의 권한은 합쳐지고, 새 기능의 권한은 기존 사용자 정의 역할에 자동 추가되지 않습니다. 역할은 최대 100개, 한 사람의 역할 지정은 최대 32개입니다.

역할을 지정하는 것만으로 비공개 문서·데이터베이스를 읽거나 편집할 수 있게 되지는 않습니다. 그룹 구성원을 변경하면 그 그룹을 통해 부여된 기존 문서 접근 권한은 달라질 수 있습니다. 가족 로그인·SCIM 토큰·보안 정책·백업 등의 소유자 권한은 따로 유지합니다.

멤버 삭제·비활성화·게스트/소유자 전환·이메일 변경·로그인 계정 연결 해제와 재연결 시 이전 지정은 무효가 됩니다. 다시 활성화하거나 같은 멤버 ID를 만들더라도 소유자가 새로 지정해야 합니다. 기존 로그인 계정의 비밀번호만 재설정하는 경우에는 지정을 유지합니다. 역할을 삭제한 뒤 같은 ID로 다른 역할을 복원해도 이전 지정이 살아나지 않도록 역할별 내부 nonce를 함께 확인합니다.

저장 요청에는 화면을 열었을 때의 revision을 포함합니다. 다른 관리자가 설정을 바꾸거나 멤버 상태가 변경되면 409로 중단하므로 최신 목록을 다시 확인해야 합니다. 전송 결과가 불확실하거나 저장 후 권한 확인이 실패했을 때 자동으로 쓰기를 반복하지 않습니다.

관리 화면은 온라인에서만 사용하며 역할 정보는 오프라인 캐시에 저장하지 않습니다. 화면을 여는 때와 각 요청 전후에 서버 권한을 다시 확인하고, 열린 동안 5초 간격 및 포커스 복귀 시에도 확인합니다. 로그아웃·계정 전환·오프라인 전환·프로필 삭제 시 임시 데이터를 지웁니다. 이미 전달받은 내용을 서버가 기기에서 즉시 회수하는 보장은 아닙니다.

API는 `GET /api/admin/self`, 소유자 전용 `GET/POST /api/admin/roles`, `PATCH/DELETE /api/admin/roles/{id}`, `PUT /api/admin/assignments/{member_id}`입니다. 역할·지정 변경은 감사 기록과 접근 revision을 같은 트랜잭션에서 갱신합니다. 일반 멤버 API의 추가 필드, 그룹, SCIM, 문서 가져오기, 오프라인 동기화로 관리 역할을 만들 수 없습니다.

콘텐츠 검색·CSV·권한 관리·게시 관리의 새 4개 액션도 실제 클라우드·Chrome에서 검사하고 API 22에 배포했습니다. 새 액션은 콘텐츠 검색 권한을 함께 선택해야 합니다. 자세한 범위는 [관리자 콘텐츠 검색](ADMIN_CONTENT.md)을 확인하세요. 조직 단위 여러 워크스페이스, 준비된 전체 관리 역할, 법적 보존, 원본 전체 분석 탭도 남아 있습니다. 기존 검증 페이지 목록이나 활동 집계를 이 기능들의 완료 증거로 취급하지 않습니다.

원본 요구의 근거와 미확인 범위는 [관리 기능 조사](research/admin-governance-original.json)에 구분했습니다. 정적 TypeScript 검사기는 추가 설치하지 않았으며, 실행 검사와 소스 검토를 정적 타입 검사 완료로 표시하지 않습니다.

복원은 `content.restore.manage`와 `content.search.read`를 함께 지정합니다. API 24는 총 11개 액션을 지원하며 기존 역할 목록을 자동 확대하지 않습니다. 복원 권한만으로 본문을 조회하지 않으며, 개인 복원을 명시적으로 실행하면 그 페이지의 소유자가 되어 접근합니다. [복원 범위](ADMIN_CONTENT.md#휴지통-페이지-복원)를 확인하세요.
