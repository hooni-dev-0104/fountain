# 공동 편집과 오프라인 저장

Fountain의 문자 병합 프로토콜은 공개 기능 명세를 참고해 별도로 구현했다. Notion의 비공개 편집 프로토콜이나 서버 코드를 복원한 결과는 아니다. 이전 [REA 분석](research/notion-rea.md)에서 확인한 공개 클라이언트 자산의 범위도 그대로 유지한다.

## 병합과 저장

문자는 유니코드 코드포인트 단위 RGA, 문자 서식과 블록 위치·속성은 Lamport 시계와 클라이언트 식별자로 비교하는 LWW 레지스터를 사용한다. 탭마다 식별자를 새로 만들고 관측한 최대 시계보다 큰 값을 보낸다. 서로 다른 위치·같은 위치의 삽입은 모두 보존하며, 같은 서식·블록 위치의 동시 수정은 결정적인 순서로 하나를 선택한다. 사용자 의도가 항상 같은 위치로 재현된다는 보장은 없다.

삭제된 문자의 식별자와 앵커를 유지하며, 아직 도착하지 않은 문자에 대한 삭제·서식도 저장한다. 새 연산의 삭제는 아래의 작업별 실행 취소로 되돌릴 수 있지만, 이전 형식의 영구 삭제는 복원하지 않는다. 알 수 없는 문자 앵커의 후속 문자는 앵커가 도착할 때까지 표시하지 않는다. 잘못된 블록 부모·순환은 결정적으로 정리한다. 공개 상태는 삭제된 내용과 서식을 제거하고 병합에 필요한 식별자·앵커·삭제 표시를 유지한다. 문자 조합이나 이모지의 그래핌 전체를 하나의 문자로 취급하지는 않는다.

연산을 적용할 때 문서와 협업 상태, 이력, 감사 로그를 하나의 원본 DB 트랜잭션에 저장한다. SQLite와 선택 PostgreSQL 저장소 모두 같은 경계를 사용한다. 같은 연산의 재전송은 ACK만 반환하며, 같은 ID에 다른 내용을 넣으면 거절한다. 연속 편집의 저장 버전은 30초 구간으로 묶고, 이력의 보존 기한은 두지 않는다. 보기·댓글 권한은 현재 내용만 읽고, 저장 버전은 편집 권한부터 읽을 수 있다.

기존 전체 블록 저장 API와 버전 복원은 문서의 epoch를 바꾼다. 제목·잠금·권한 변경은 epoch를 바꾸지 않는다. 이전 epoch의 미전송 연산은 현재 문서에 자동 덮어쓰지 않고 복구 초안으로 보관한다. 삭제 표시와 처리한 연산 ID는 epoch가 바뀌기 전까지 누적되므로 매우 큰 문서·장기간 편집에는 압축과 부하 검증이 추가로 필요하다.

## 실행 취소와 다시 실행

블록 편집기의 실행 취소는 해당 탭에서 만든 작업만 취소한다. 이전 문서 전체를 덮어쓰지 않으며 다른 사용자의 연산을 지우지 않는다. 같은 글자를 두 사용자가 삭제했다면 한 사람의 삭제만 취소해도 글자가 나타나지 않는다. 삭제를 취소해 복원하는 글자는 원래 ID를 사용하므로 그 뒤에 들어온 원격 글자의 앵커를 유지한다. 새 블록의 생성을 취소해도 다른 사람이 추가한 글자·속성·자식이 남아 있으면 필요한 블록 틀을 보존한다.

`history.cancel`은 같은 클라이언트의 더 낮은 시계에 있는 `targets`를 지정한다. 서버는 실제 로그인한 멤버의 작업 소유권과 현재 편집 권한을 검사한다. 다시 실행은 실제 취소 연산을 취소하여 원래 작업을 재활성화한다. 원래 시계가 더 높다면 원격 속성보다 다시 우선할 수 있지만 원격 연산 자체는 보존한다. 잠금·권한·첨부 검사는 복원 결과에도 적용하며 전체 요청을 원자적으로 처리한다.

서버의 과거 값과 연산 원문은 비공개 baseline·ledger에 보관한다. 공개 응답은 현재 표시하는 값과 연산의 위치·시계만 제공한다. 브라우저는 자신이 실제 관측한 값만 출처 시계와 함께 잠시 기억한다. 실행 취소 후 승자의 값을 모르면 마지막으로 확정된 화면을 유지하고 본문 편집을 잠시 막으며, 연결 후 원본 응답으로 해결한다. 오프라인에서도 취소 연산은 기기에 보관한다. 알려지지 않은 값을 이전 값이나 기본값으로 추측해 저장하지 않는다.

탭의 실행 취소 목록은 최대 100항목이며 선택 위치·임시 값까지 약 2MiB로 제한한다. 인접한 같은 블록 입력은 최대 750ms 간격으로 묶고, 조합 입력·구조 변경·서식·첨부는 각각 한 동작으로 처리한다. 문서 닫기·새로고침·계정/epoch 변경·잠금·편집 권한 상실·거부된 작업 복구 시 목록을 비운다. 미전송 연산은 별도의 영구 큐이므로 이 제한으로 지워지지 않는다. 서버의 연산 ledger에는 아직 자동 압축이 없다.

제목과 DB 입력 폼은 입력창의 기본 실행 취소를 사용한다. 첨부의 실행 취소는 파일 블록의 표시를 바꾸며 파일 바이트를 삭제하지 않는다. 업로드 완료는 해당 생성 연산의 원본 ACK로 확인해야 하며, 이미 취소되거나 원격 삭제된 파일 블록을 업로드 재시도로 다시 만들지 않는다.

파일 연결은 생성할 원본 연산·epoch·블록 ID를 업로드 기록에 먼저 저장한 뒤 전송한다. 완료 처리 직전에 앱이 닫혀도 같은 연산만 재전송하고, 현재 보이는 파일 블록의 유무로 완료를 추측하지 않는다. 이전 형식의 완료 기록에 이 증거가 없으면 자동 재삽입을 멈추고 복구 안내를 남긴다.

새 ledger를 기록한 DB를 이전 서버 구현으로 다시 수정하면 lineage와 현재 값이 어긋날 수 있다. 서버를 내릴 때는 단순히 예전 코드만 실행하지 말고 백업·현재 데이터 보존과 epoch 교체를 포함한 변환을 검증해야 한다. 이전 웹 클라이언트의 일반 연산은 새 서버에서 계속 검증·저장한다.

검증 명령은 `python3 -m unittest tests.test_crdt tests.test_history_crdt tests.test_history_authorization tests.test_collaboration`, `python3 tests/history-parity.py`, `node tests/crdt.mjs`, `node tests/crdt-history.mjs`, `node tests/channel-history.mjs`, `node tests/browser-undo.mjs`다. 교차 언어 비교는 보정 없이 private/public 상태와 정확한 출처의 값 복구를 비교한다. PostgreSQL HTTP 회귀는 별도 시험 작업공간의 두 서버에서 취소·다시 실행·소유권·재전송 불변성을 확인한다.

## HTTP 인터페이스

| 경로 | 동작 |
| --- | --- |
| `GET /api/pages/:id/collaboration` | 현재 epoch·seq·공개 CRDT 상태·문서·권한 |
| `POST /api/pages/:id/operations` | `{epoch, ops}` 적용 후 snapshot과 `ack` ID 목록 |
| `GET /api/pages/:id/events` | SSE `snapshot`·`presence`, 접근 철회 시 `denied` 이벤트 |
| `PUT /api/pages/:id/blocks` | 기존 전체 저장·revision 충돌 검사·epoch 교체 |
| `GET /api/pages/:id/presence` | 현재 페이지의 유효한 접속 세션·선택 영역 |
| `PUT /api/pages/:id/presence` | 현재 세션의 접속 상태·커서 갱신 |
| `DELETE /api/pages/:id/presence` | 현재 세션의 해당 클라이언트 퇴장 |

연산은 한 요청에 최대 1,000개다. 문서 한 개의 블록 2,000개·블록당 문자 100,000개 제한은 로컬 자원 보호를 위한 구현 한도다. 첨부는 [5GB 청크 전송](FILES.md)과 문서 권한을 적용하며, 호환용 JSON 업로드만 기존 5MB 한도를 유지한다. 중첩·서식은 JSON 백업, HTML 게시·클립보드에 반영한다. Markdown은 기본 서식·들여쓰기를 보존하지만 색상과 모든 편집기 구조를 완전히 왕복하지는 않는다.

SSE는 과거 연산 로그 대신 현재의 정제된 상태만 전달한다. 약 0.5초마다 최초 쿠키로 세션과 현재 그룹·문서 권한을 다시 확인하며, 문서 seq가 같아도 제목·잠금·권한 변경을 전달한다. 쓰기는 SQLite 쓰기 권한을 확보한 뒤 인증·ACL을 확인하므로 여러 서버 연결의 철회 경쟁도 검사한다. AI 공급자 네트워크 대기에는 워크스페이스 잠금을 유지하지 않는다.

## 접속자와 원격 커서

상단에는 현재 페이지를 열어 접속 상태를 갱신하는 세션을 표시한다. 같은 계정의 다른 로그인 세션도 각각 표시하며, 보기 권한 사용자도 커서·선택 영역을 공유할 수 있다. 이름과 계정은 서버가 현재 세션에서 확인한다. 세션 만료·비밀번호 변경·계정 비활성화·페이지나 그룹 권한 철회 후에는 기존 접속 상태를 제외한다.

화면이 보이는 동안 5초마다 상태를 갱신하며, 마지막 갱신 뒤 15초가 지나면 접속 상태가 만료된다. 페이지 이동·탭 숨김 때는 퇴장을 전송하고, 오프라인에서는 표시와 전송을 멈춘다. 아직 서버에 생성되지 않은 로컬 페이지는 접속 상태를 보내지 않는다. 늦은 응답은 로그인 세대·문서 epoch·revision을 검사하여 폐기한다.

선택 영역에는 블록과 RGA 문자 식별자·코드포인트 위치만 전송하고 선택한 원문은 보내지 않는다. 원격 삽입 후에도 문자 앵커로 위치를 계산하며, 삭제되거나 알 수 없는 앵커는 숨긴다. 표시용 오버레이는 편집기 본문 DOM을 고치지 않는다. 별도 SSE `presence` 이벤트를 사용하므로 커서 이동으로 문서 snapshot을 다시 보내거나 문서 revision·연산 seq·이력·감사 기록을 바꾸지 않는다.

접속 기록은 서버에 임시 보관하며 IndexedDB·서비스 워커 캐시·전체 백업에는 포함하지 않는다. 클라이언트는 채널마다 새 식별자와 증가하는 seq를 사용한다. 퇴장·만료 후에도 최고 seq를 60초 더 보관하여 그동안 늦은 갱신이 접속자를 되살리지 못하게 한다. 이 기간이 지난 기록은 정리되므로 영구적인 재전송 방지는 아니며, 오프라인 접속 기록을 저장하거나 재생하지 않는다.

## 브라우저 데이터 수명

snapshot의 `current_member_id`·`session_binding`은 쿠키로 인증한 실제 계정과 로그인 세대를 나타낸다. 브라우저는 앞서 읽은 세션과 다르면 결과를 해당 프로필에 저장하지 않는다. `access_revision`은 문서 연산 seq와 별도로 권한·멤버·그룹 변경 순서를 표시하여 늦은 응답이 새 권한을 덮지 않게 한다. 공개 처리 연산 목록에는 ID와 ACK 표시만 보내고 원문 해시는 노출하지 않는다.

서비스 워커에는 빈 앱 화면과 정적 스크립트·스타일만 저장한다. API·게시 문서·양식 응답은 서비스 워커 캐시에 넣지 않는다. 문서 snapshot, 미전송 연산, 복구 초안은 IndexedDB에 따로 저장하며 origin·워크스페이스·멤버·로그인 세대·페이지로 구분한다. 연산은 개별 ID 레코드로 저장하므로 두 탭이 같은 배열을 덮어쓰지 않으며 ACK 받은 ID만 지운다.

비밀번호·로그인 토큰은 저장하지 않는다. 로그아웃은 해당 사용자의 로컬 자료를 지우고 다른 탭에도 알린다. 이전 로그인 세대의 늦은 응답은 캐시를 다시 만들 수 없다. 계정 세션 만료 후에는 오프라인 자료를 열지 않으며, 인증 없는 로컬 모드의 오프라인 프로필도 24시간으로 제한한다. 온라인 API의 401·403·404는 오프라인 자료로 대체하지 않는다. 서버가 없는 동안 원격에서 바뀐 권한을 즉시 알 수는 없으므로, 이미 다운로드한 내용은 유효한 로컬 프로필 기간 동안 남는다.

브라우저 데이터는 같은 OS·브라우저 프로필을 사용할 수 있는 사람에게 암호화된 별도 금고를 제공하지 않는다. 로그아웃 전에 전송되지 않은 초안이 있다면 내보내거나 동기화 상태를 확인해야 한다. 전체 SQLite 백업은 협업 상태를 보존하지만 세션·접속 상태·임시 클립보드·이전 브라우저 캐시 식별자는 제외한다.

서비스 워커로 서버 없이 다시 여는 기능은 `localhost` 또는 브라우저가 신뢰하는 HTTPS 환경이 필요하다. 일반 LAN HTTP 주소에서는 이미 열린 탭의 로컬 초안 저장과 재접속을 사용할 수 있지만 서버 없는 새로고침을 보장하지 않는다. 서버의 `--tls-cert`·`--tls-key` 옵션으로 직접 HTTPS를 제공할 수 있으며, 기기에서 인증서를 신뢰해야 한다. DB 구조・권한・설정 변경과 첨부 업로드는 서버 연결이 필요하다.

## DB·새 페이지 동기화 기반

`POST /api/sync`는 페이지 생성·메타데이터 수정과 DB 행 생성·수정·삭제를 위한 서버 인터페이스다. 앱 화면은 열린 DB를 기기에 보관하고, 오프라인 행 편집·추가·삭제와 새 페이지·자식 페이지 생성을 이 인터페이스에 연결한다. 네이티브 클라이언트는 미연결이며 [플랫폼 설계](PLATFORMS.md)에서 남은 경계를 관리한다.

요청은 `{workspace_id, session_binding, operations}`이며 한 번에 최대 50개 작업을 받는다. 작업은 변경 불가능한 `id`, `kind`, `target_id`, `body`를 가진다. 행 작업은 `database_id`, 수정은 영향을 주는 필드의 이전 값과 속성 정의를 `base`로 전달한다. `depends_on`은 먼저 적용할 자기 작업의 ID다. 새 페이지는 클라이언트 UUID와 `document_epoch`를 보존하여 이후 문서 연산의 기준을 맞춘다.

서버는 작업마다 인증과 권한을 다시 검사하고 변경·감사·중복 방지 기록을 한 트랜잭션으로 저장한다. 같은 사용자의 동일 작업 재전송은 중복 적용하지 않는다. 독립 필드 변경은 병합하고, 같은 필드나 속성 정의가 달라지면 충돌로 남긴다. 한 작업의 실패로 앞서 적용한 다른 작업을 되돌리지 않는다. 하위 행 삭제는 현재 전체 하위 항목과 각각의 수정 시각·권한이 일치해야 한다.

응답의 작업별 상태는 `applied`, `conflict`, `denied`, `invalid`, `deferred`다. 실패한 변경을 자동 폐기하거나 같은 ID의 내용을 바꿔 재전송하면 안 된다. 충돌을 해결해 다시 적용하려면 새 ID와 새로운 기준 값을 만들고 해당 변경에 의존하는 후속 작업도 함께 처리해야 한다.

작업 응답과 원본 DB·작업공간 조회에는 `data_revision`을 제공한다. 클라이언트는 적용 응답을 영구 보관하고, 그 revision 이상인 원본 스냅샷을 저장한 뒤에만 미전송 기록을 정리해야 한다. IndexedDB v2는 기존 문서 저장소를 보존하면서 DB 스냅샷·작업별 큐·로컬 새 페이지 준비를 지원한다. 읽기 권한이 철회되면 원본 캐시는 지우고 새 작업 큐의 거부 기록은 자동 재생하지 않는 복구 자료로 남긴다. 기기에서 명시적으로 로그아웃하면 이 자료도 지운다.

새 페이지의 생성 작업과 초기 CRDT 상태는 함께 저장한다. 서버가 생성을 적용했다는 기록이 기기에 남기 전에는 문서 조회·SSE·본문 전송을 시작하지 않는다. 생성 후에는 같은 epoch로 미전송 본문을 병합하며, 다른 화면으로 이동해도 재접속 때 생성된 문서의 본문을 전송한다. 제목·아이콘·표지·즐겨찾기도 개별 변경으로 보관한다.

행 편집은 사용자가 입력창을 열 때 본 값과 속성 정의를 기준으로 비교한다. 입력 중 다른 기기의 새 값을 받아도 그 값을 사용자의 수정 기준으로 바꾸지 않는다. 수식·롤업, 날짜 의존관계의 연쇄 조정은 서버에서 최종 계산한다. 캐시에서 읽을 수 있는 자료만 오프라인으로 열 수 있으며, 새 DB 구조를 만드는 기능은 서버 연결이 필요하다.

**기기 저장과 동기화** 화면은 변경별 대기·충돌·권한 거부 상태와 복구 내려받기·재적용·폐기를 제공한다. 재적용은 최신 기준과 새 작업 ID를 만들고 의존하는 후속 작업을 함께 교체한다. 새 페이지 재적용은 페이지 ID·epoch·기기에 보관한 본문을 유지한다. 이미 같은 ID의 다른 자료가 존재하거나 새 속성 타입과 이전 입력이 맞지 않으면 강제로 바꾸지 않고 복구 기록을 보존한다.

복구 JSON은 해당 사용자가 제출하려던 변경과 로컬 새 페이지의 본문·미전송 연산을 포함하며 로그인 비밀은 포함하지 않는다. 내보낸 파일을 자동으로 가져와 재생하는 기능은 아직 없다. 변경을 폐기하면 의존 작업도 함께 확인하고 원자적으로 지운다. 기기에만 있는 새 페이지를 폐기하면 그 문서의 본문·초안도 삭제하고 다른 탭의 늦은 저장을 막는다. 서버에 이미 적용된 변경은 폐기로 되돌리지 않는다.

## 공개 명세와 차이

Fountain은 열린 문서를 자동 보관하고, 부팅 뒤 즐겨찾기와 최근 문서 목록에서 최대 20개를 추가로 보관한다. 최근 목록은 로그인별 최대 12개를 유지한다. 더 많은 문서는 연결된 상태에서 직접 열어 보관할 수 있다. 자동 다운로드 설정·전체 보관 목록 관리 UI는 아직 제공하지 않는다. 복구 기준 상태가 없어 연산만 남은 경우에는 복구 파일 내려받기만 제공하고 초안을 지우지 않는다.

Notion은 앱에서 페이지를 내려받아 오프라인 편집하며, 유료 플랜은 최근·즐겨찾기 페이지를 자동 내려받는다고 안내한다. Fountain은 브라우저 IndexedDB와 서비스 워커로 별도 구현한다. [Notion 오프라인 안내](https://www.notion.com/help/use-pages-offline)

Notion의 이력 열람에는 편집 이상 권한이 필요하며, 플랜에 따라 보존 기간이 다르다. Fountain은 편집 권한 검사를 적용하고 로컬 이력에 보존 기한을 두지 않는다. [Notion 삭제·복원·이력 안내](https://www.notion.com/help/duplicate-delete-and-restore-content)
