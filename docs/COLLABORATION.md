# 공동 편집과 오프라인 저장

Fountain의 문자 병합 프로토콜은 공개 기능 명세를 참고해 별도로 구현했다. Notion의 비공개 편집 프로토콜이나 서버 코드를 복원한 결과는 아니다. 이전 [REA 분석](research/notion-rea.md)에서 확인한 공개 클라이언트 자산의 범위도 그대로 유지한다.

## 병합과 저장

문자는 유니코드 코드포인트 단위 RGA, 문자 서식과 블록 위치·속성은 Lamport 시계와 클라이언트 식별자로 비교하는 LWW 레지스터를 사용한다. 탭마다 식별자를 새로 만들고 관측한 최대 시계보다 큰 값을 보낸다. 서로 다른 위치·같은 위치의 삽입은 모두 보존하며, 같은 서식·블록 위치의 동시 수정은 결정적인 순서로 하나를 선택한다. 사용자 의도가 항상 같은 위치로 재현된다는 보장은 없다.

삭제 표시는 영구 보존하며, 아직 도착하지 않은 문자에 대한 삭제·서식도 저장한다. 알 수 없는 문자 앵커의 후속 문자는 앵커가 도착할 때까지 표시하지 않는다. 잘못된 블록 부모·순환은 결정적으로 정리한다. 공개 상태는 삭제된 내용과 서식을 제거하고 병합에 필요한 식별자·앵커·삭제 표시를 유지한다. 문자 조합이나 이모지의 그래핌 전체를 하나의 문자로 취급하지는 않는다.

연산을 적용할 때 문서와 협업 상태, 이력, 감사 로그를 하나의 SQLite 트랜잭션에 저장한다. 같은 연산의 재전송은 ACK만 반환하며, 같은 ID에 다른 내용을 넣으면 거절한다. 연속 편집의 이력은 30초 구간으로 묶고, 이력의 보존 기한은 두지 않는다. 보기·댓글 권한은 현재 내용만 읽고, 이력은 편집 권한부터 읽을 수 있다.

기존 전체 블록 저장 API와 버전 복원은 문서의 epoch를 바꾼다. 제목·잠금·권한 변경은 epoch를 바꾸지 않는다. 이전 epoch의 미전송 연산은 현재 문서에 자동 덮어쓰지 않고 복구 초안으로 보관한다. 삭제 표시와 처리한 연산 ID는 epoch가 바뀌기 전까지 누적되므로 매우 큰 문서·장기간 편집에는 압축과 부하 검증이 추가로 필요하다.

## HTTP 인터페이스

| 경로 | 동작 |
| --- | --- |
| `GET /api/pages/:id/collaboration` | 현재 epoch·seq·공개 CRDT 상태·문서·권한 |
| `POST /api/pages/:id/operations` | `{epoch, ops}` 적용 후 snapshot과 `ack` ID 목록 |
| `GET /api/pages/:id/events` | SSE `snapshot`, 접근 철회 시 `denied` 이벤트 |
| `PUT /api/pages/:id/blocks` | 기존 전체 저장·revision 충돌 검사·epoch 교체 |

연산은 한 요청에 최대 1,000개다. 문서 한 개의 블록 2,000개·블록당 문자 100,000개 제한은 로컬 자원 보호를 위한 구현 한도다. 첨부는 기존 5MB 한도와 문서 권한을 적용한다. 중첩·서식은 JSON 백업, HTML 게시·클립보드에 반영한다. Markdown은 기본 서식·들여쓰기를 보존하지만 색상과 모든 편집기 구조를 완전히 왕복하지는 않는다.

SSE는 과거 연산 로그 대신 현재의 정제된 상태만 전달한다. 약 0.5초마다 최초 쿠키로 세션과 현재 그룹·문서 권한을 다시 확인하며, 문서 seq가 같아도 제목·잠금·권한 변경을 전달한다. 쓰기는 SQLite 쓰기 권한을 확보한 뒤 인증·ACL을 확인하므로 여러 서버 연결의 철회 경쟁도 검사한다. AI 공급자 네트워크 대기에는 워크스페이스 잠금을 유지하지 않는다.

## 브라우저 데이터 수명

snapshot의 `current_member_id`·`session_binding`은 쿠키로 인증한 실제 계정과 로그인 세대를 나타낸다. 브라우저는 앞서 읽은 세션과 다르면 결과를 해당 프로필에 저장하지 않는다. `access_revision`은 문서 연산 seq와 별도로 권한·멤버·그룹 변경 순서를 표시하여 늦은 응답이 새 권한을 덮지 않게 한다. 공개 처리 연산 목록에는 ID와 ACK 표시만 보내고 원문 해시는 노출하지 않는다.

서비스 워커에는 빈 앱 화면과 정적 스크립트·스타일만 저장한다. API·게시 문서·양식 응답은 서비스 워커 캐시에 넣지 않는다. 문서 snapshot, 미전송 연산, 복구 초안은 IndexedDB에 따로 저장하며 origin·워크스페이스·멤버·로그인 세대·페이지로 구분한다. 연산은 개별 ID 레코드로 저장하므로 두 탭이 같은 배열을 덮어쓰지 않으며 ACK 받은 ID만 지운다.

비밀번호·로그인 토큰은 저장하지 않는다. 로그아웃은 해당 사용자의 로컬 자료를 지우고 다른 탭에도 알린다. 이전 로그인 세대의 늦은 응답은 캐시를 다시 만들 수 없다. 계정 세션 만료 후에는 오프라인 자료를 열지 않으며, 인증 없는 로컬 모드의 오프라인 프로필도 24시간으로 제한한다. 온라인 API의 401·403·404는 오프라인 자료로 대체하지 않는다. 서버가 없는 동안 원격에서 바뀐 권한을 즉시 알 수는 없으므로, 이미 다운로드한 내용은 유효한 로컬 프로필 기간 동안 남는다.

브라우저 데이터는 같은 OS·브라우저 프로필을 사용할 수 있는 사람에게 암호화된 별도 금고를 제공하지 않는다. 로그아웃 전에 전송되지 않은 초안이 있다면 내보내거나 동기화 상태를 확인해야 한다. 전체 SQLite 백업은 협업 상태를 보존하지만 세션·임시 클립보드·이전 브라우저 캐시 식별자는 제외한다.

서비스 워커로 서버 없이 다시 여는 기능은 `localhost` 또는 브라우저가 신뢰하는 HTTPS 환경이 필요하다. 일반 LAN HTTP 주소에서는 이미 열린 탭의 로컬 초안 저장과 재접속을 사용할 수 있지만 서버 없는 새로고침을 보장하지 않는다. 현재 서버는 직접 TLS를 제공하지 않는다. DB 행·설정·권한·새 페이지 생성·첨부 업로드의 완전한 오프라인 작업은 아직 지원하지 않는다.

## 공개 명세와 차이

Fountain은 열린 문서를 자동 보관하고, 부팅 뒤 즐겨찾기와 최근 문서 목록에서 최대 20개를 추가로 보관한다. 최근 목록은 로그인별 최대 12개를 유지한다. 더 많은 문서는 연결된 상태에서 직접 열어 보관할 수 있다. 자동 다운로드 설정·전체 보관 목록 관리 UI는 아직 제공하지 않는다. 복구 기준 상태가 없어 연산만 남은 경우에는 복구 파일 내려받기만 제공하고 초안을 지우지 않는다.

Notion은 앱에서 페이지를 내려받아 오프라인 편집하며, 유료 플랜은 최근·즐겨찾기 페이지를 자동 내려받는다고 안내한다. Fountain은 브라우저 IndexedDB와 서비스 워커로 별도 구현한다. [Notion 오프라인 안내](https://www.notion.com/help/use-pages-offline)

Notion의 이력 열람에는 편집 이상 권한이 필요하며, 플랜에 따라 보존 기간이 다르다. Fountain은 편집 권한 검사를 적용하고 로컬 이력에 보존 기한을 두지 않는다. [Notion 삭제·복원·이력 안내](https://www.notion.com/help/duplicate-delete-and-restore-content)
