`GET /api/capabilities`와 설정의 기능 제공 현황에도 상태를 표시한다. 구현된 API와 실제 운영 연결은 다르다. 현재 원본의 실사용 소유자 연결과 공개 웹 호스트는 아직 없으며, Cron·SCIM은 격리된 실제 백엔드 검증을 통과했어도 원본 예약이나 외부 IdP가 자동으로 연결된 것은 아니다. 클라우드 AI 공급자도 미설정이다.

Python 호환 모드의 계정 활성화·공용 로그인은 이전 동작을 유지한다. 작업공간 소유자는 비공개 페이지에도 접근할 수 있고, 멤버 관리자는 비공개 콘텐츠 권한을 자동으로 받지 않는다. 외부 LLM의 무보존 보증과 전담 지원은 로컬 코드만으로 제공할 수 없다.

전체 목표의 구조화된 미검증 항목은 [추적 목록](rebuild/features.json)과 [범위 보고서](rebuild/parity-report.md)에 보존한다. 각 영역의 일부 검사 통과를 영역 전체 또는 전체 제품의 동등성으로 확대하지 않는다.

## 검증 원칙

문서·행·설정은 실제 원본 DB(SQLite 또는 PostgreSQL)에 저장한다. 브라우저 테스트는 실제 HTTP 서버에서 편집·저장·복원과 화면 이동을 수행하며 PostgreSQL에서는 독립 서버 두 개도 검증했다. AI 어댑터의 테스트 공급자는 테스트 전용 로컬 HTTP fixture이며 실제 모델 품질이나 구독 연결 성공의 증거가 아니다. REA 분석 범위는 [분석 기록](research/notion-rea.md)에 별도로 남겼다.

## 계정과 권한 검증

검색·워크스페이스 목록·개별 문서 API에 같은 권한을 적용한다. 관계·롤업 계산은 읽을 수 있는 행만 사용하고, 행 수정 응답의 관계 ID도 필터링한다. 첨부 링크만 알아도 비공개 파일을 내려받을 수 없으며, 다른 페이지에 파일 ID를 붙여 권한을 우회할 수도 없다. 전체 백업·보안 설정·감사 로그는 소유자에게만 허용한다. 멤버 관리자는 계정 소유자를 만들거나 마지막 소유자를 비활성화할 수 없다. 계정 비활성화·삭제·비밀번호 변경은 기존 세션을 철회한다.

## 작업 일정과 예약 자동화

DB의 일정 설정에서 하위 항목과 의존관계를 켜고 날짜 속성을 선택한다. 일정 조정은 없음·겹칠 때 이동·간격 유지 모드를 제공하며, 수정할 수 없는 후속 행은 바꾸지 않는다. 보이지 않는 부모·선행 항목 ID는 응답에서 가리고, 보이는 연결만 수정해도 숨긴 기존 연결은 보존한다. 하위 항목을 삭제할 권한이 없으면 부모 삭제도 거부한다. 복제는 읽을 수 있는 전체 하위 항목을 새 ID와 비공개 권한으로 만들며, 읽을 수 없는 외부 연결은 복사하지 않는다.

자동 조정은 날짜 또는 시간대가 있는 날짜·시간의 동일 정밀도끼리 지원한다. 두 정밀도가 섞인 연결의 자동 조정은 오류를 표시한다. 주말 회피는 기간 길이를 유지하면서 양 끝이 평일이 될 때까지 전체 기간을 앞으로 옮긴다. 날짜·시간은 입력한 UTC 오프셋을 보존하며, IANA 시간대 메타데이터로 오프셋을 다시 해석하지 않는다. 작업 그래프 한 번의 검증은 노드·연결 각각 10,000개까지다. 일반 DB 항목에는 별도 과금 한도가 없다.

예약은 분·시간·일·주·월·년 주기, IANA 시간대, 시작·선택 종료 시각을 저장한다. 월말과 연간 주기는 최초 달력 날짜를 기준으로 계산하며, 월말에 맞춰 잠시 줄인 날짜가 다음 달에도 계속 줄어들지는 않는다. 일광절약시간의 존재하지 않는 반복 시각은 앞으로 조정하고 중복 시각은 한 번만 실행한다. 놓친 실행은 한 번으로 합치며, 예약 실행 기록은 수동 실행과 구분한다. 자동화 작성자가 비활성화되거나 DB 전체 권한을 잃으면 실행하지 않는다. Python 호환 모드는 SQLite 잠금과 영구 실행 식별자를 사용하고, 클라우드는 Supabase Cron·broker·worker의 현재 권한·세대·receipt 검사로 중복과 늦은 실행을 막는다. 원본 작업공간의 예약 등록은 아직 남아 있다.

이 동작 중 공개 Notion 명세에서 확인한 부분과 자체 설계한 경계 처리는 [DB 조사 기록](research/notion-databases.md)에 구분했다. 원본의 일정 알고리즘을 복원했다는 의미는 아니다.

## 문서 공동 편집과 오프라인

문자·서식 연산은 전체 문서를 덮어쓰지 않고 병합하며, 재전송한 연산은 중복 적용하지 않는다. 실시간 연결도 세션과 현재 문서·그룹 권한을 다시 검사한다. 이력 열람은 편집 이상 권한에만 허용하고, 공개 협업 상태에는 삭제 내용과 원문 연산 해시를 보내지 않는다.

현재 페이지를 보고 있는 세션의 이름·커서·선택 영역을 표시하며, 보기 권한 사용자도 참여한다. 접속 상태는 5초마다 갱신하고 마지막 갱신 뒤 15초가 지나면 만료된다. 문자 식별자 앵커로 원격 삽입 뒤 위치를 맞추고, 사라진 앵커의 선택 영역은 숨긴다. 접속 정보는 문서 본문·revision·이력을 바꾸지 않으며 오프라인 캐시와 전체 백업에도 포함하지 않는다.

기존 전체 저장과 버전 복원은 편집 epoch를 교체한다. 이전 epoch의 미전송 내용은 복구 초안으로 보관하여 내보내거나 새 블록으로 추가할 수 있다. 로그아웃·권한 철회 뒤의 늦은 응답은 삭제한 로컬 자료를 다시 만들지 못하도록 로그인·문서별 폐기 표시를 저장한다. 브라우저 캐시가 읽기 거절 응답을 대신하지 않는다.

서비스 워커를 통한 오프라인 새로고침은 localhost 또는 신뢰하는 HTTPS가 필요하다. 가족 LAN의 일반 HTTP 주소에서는 이미 열린 탭의 초안 저장·재접속을 사용할 수 있고, 직접 HTTPS 옵션은 기기에서 신뢰하는 인증서가 필요하다. 세부 API, 한도와 저장 수명은 [공동 편집 안내](COLLABORATION.md)에 기록했다.


공동 편집의 서버 ACK는 기기 저장을 확인한 canonical snapshot의 같은 epoch에서 확인된 작업만 삭제한다. 웹은 snapshot 저장과 대기 작업 삭제를 하나의 IndexedDB 트랜잭션으로 묶고, 모바일 기본 경로는 네이티브 SQLite COMMIT까지 확인한다. 저장 실패나 불확실한 응답은 원문을 보존한 채 다시 확인한다.

기본 활성화 021 검증에서는 두 모바일 플랫폼이 별도 override 없이 실제 bridge의 설정과 5단계를 통과했다. 네이티브가 COMMIT으로 확인한 현재 로그인 범위의 대기 편집은 재시작·IndexedDB 제거 뒤 복원되지만, 미확인 입력이나 다른 로그인 원문을 보존한 내부 IndexedDB 저널은 같은 내구성 보장이 없다. 앱 삭제·전원 차단·물리 기기·전체 다섯 플랫폼 검증을 뜻하지 않는다.
