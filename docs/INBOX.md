# 알림함

사이드바의 **알림함**에서 내가 검증 담당자인 문서와 [데이터베이스 행](DATABASE_VERIFICATION.md)의 만료를 확인한다. 소유자·관리자·멤버·게스트가 각자의 알림을 보며, 기존 **업데이트**의 소유자용 감사 로그와 구분된다.

**전체**, **읽지 않음**, **보관함**으로 나누어 보고 읽음·안 읽음, 보관·보관 해제를 선택한다. 제목을 누르면 읽음으로 표시한 뒤 해당 문서 또는 행의 상세 화면을 연다. 목록은 새로고침하거나 **더 보기**로 이어 읽는다. 상태는 로그인한 멤버별로 서버에 저장하므로 같은 계정의 다른 기기에서도 다음 조회 때 반영된다. 다른 가족 계정의 상태는 바뀌지 않는다.

이 목록은 **현재 만료된 검증에 대한 알림**이다. 무기한 검증, 아직 만료되지 않은 검증, 잘못 저장된 정보와 삭제한 문서는 표시하지 않는다. 검증 담당자에서 빠지거나 문서 접근 권한을 잃으면 목록과 개수에서도 제외한다. 재검증하거나 검증을 해제하면 이전 알림은 사라진다. 새 검증 회차가 만료되면 새 읽지 않은 알림이 생기며 일반 제목·본문 편집만으로 읽음 상태가 초기화되지는 않는다.

알림은 서버에 연결한 상태에서 조회·변경한다. 오프라인 변경 대기열이나 문서 캐시에 알림 제목을 저장하지 않는다. 계정 전환·로그아웃·기기 보관 점검으로 화면이 닫히면 이전 제목을 지우고 늦게 도착한 응답을 적용하지 않는다.

## API와 저장

`GET /api/inbox?filter=all&limit=50&offset=0`

`filter`는 `all`, `unread`, `archived`다. 기본 `all`은 보관하지 않은 알림이다. `limit`은 1~100, `offset`은 0~1,000,000의 정수이며 기본값은 각각 50과 0이다. 알 수 없는 필드·중복·빈 값은 거절한다. 일반 애플리케이션의 URL 보안 경계에서 먼저 차단되는 요청은 도메인 검증에 도달하지 않는다.

응답은 `items`, `unread_count`, `total`, `has_more`, `offset`, `limit`이다. 항목의 공통 필드는 `id`, `type: "verification.expired"`, 현재 `title`·`icon`, `verified_at`, `expires_at`, `read`, `archived`다. 기존 페이지 항목은 `page_id`를 유지하고, 행 항목은 `resource_type: "row"`, `database_id`, `row_id`를 포함한다. 담당자 목록·숨겨진 인원 수·본문은 포함하지 않는다. 행 제목은 첫 제목 속성에서 읽는다. 만료 시각 내림차순, 같은 시각이면 ID 순이다.

`PATCH /api/inbox/{id}`에는 `{"read":true}` 또는 `{"archived":true}`처럼 하나 이상의 불리언 상태를 보낸다. 두 상태를 함께 보낼 수 있다. 수신자는 요청 본문이 아닌 현재 인증된 멤버로 고정한다. 현재 회차·담당자·문서 권한을 다시 검사하며 더 이상 해당하지 않는 ID는 404다.

읽음·보관은 별도 `inbox_receipt`에 저장한다. 페이지·행의 본문·소유자·ACL·revision을 수정하지 않는다. 페이지의 비공개 `cycle_revision`, 행의 속성 세대와 검증 회차로 같은 시각에 다시 검증한 기록도 구분한다. 행 담당자·현재 데이터베이스/행 권한을 다시 검사하고, 속성을 제거 후 재추가하면 이전 회차의 알림은 재사용하지 않는다. 비공개 회차 정보는 공개 검증 DTO에 포함하지 않는다. 이전 페이지 검증 형식도 지원한다. 단순 알림 조회는 문서·행·설정·감사 로그·개인 읽음 기록을 변경하지 않는다. 기존 트랜잭션의 내부 승인 기록과 인증 세션 유지 기록은 생성될 수 있다.

클라우드 조회에는 페이지 헤더와 서버가 계산한 `database_verification_rows_v1`의 데이터베이스·행 헤더를 사용한다. 행 헤더는 담당자·첫 제목·기존 항목별 권한에 필요한 값과 검증 정보를 제한해서 포함하며, 관계없는 일반 속성 본문을 읽지 않는다. 저장된 동명 메타데이터로 계산 결과를 대체할 수 없다. 기존 응답·트랜잭션 용량 한도는 유지한다.

## 원본 근거와 남은 범위

[Notion 검증 안내](https://www.notion.com/help/wikis-and-verified-pages)에서 만료 시 담당자에게 알림함·이메일로 안내하는 동작을, [알림함 안내](https://www.notion.com/help/updates-and-notifications)에서 읽음·보관 동작을 확인했다. 이는 공식 문서의 제품 행동이며 Notion의 비공개 알림 서버를 복원했다는 의미가 아니다.

현재 구현은 조회 시의 만료 상태와 개인 상태 저장이다. 앱이 닫힌 동안의 만료 사건을 보존하는 배경 전달, 이메일·OS 푸시, 댓글·멘션·초대·자동화 등 다른 알림 종류와 전체 Notion 알림함 동등성은 아직 미완료다. 실제 이메일이나 푸시를 발송하지 않는다. 실행 범위와 증거는 [검증 기록](research/inbox-evidence.json)에 기록한다.
