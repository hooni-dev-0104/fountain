# 계정과 여러 작업공간

하나의 계정으로 여러 작업공간을 선택하는 기능을 구현하고 검증 중입니다.
웹과 macOS의 실제 클라우드 경로를 검증했지만, 현재 모바일의 작업공간 전환에는
해결 중인 문제가 있으므로 다섯 플랫폼 전체 검증을 완료한 상태로 취급하지 않습니다.

## 계정과 자료 범위

계정 로그인은 작업공간별 자료 접근과 구분합니다. 작업공간을 열 때 서버가 현재
멤버십과 권한을 확인하고 해당 범위의 연결을 발급합니다. 공개 선택 목록이나
브라우저의 이전 선택 정보만으로 접근 권한을 만들지 않습니다. 같은 문서 식별자가
여러 작업공간에 있어도 서로 다른 자료로 처리합니다.

실제 계정 인증, 데이터, 파일과 서버 작업은 Supabase를 사용합니다. Vercel은 정적
웹 화면과 게시 페이지의 표시를 담당합니다. 게시 경로의 전달 함수는 자료 저장소나
별도의 계정 서버가 아니며, 필요한 쿠키와 해당 작업공간 범위만 전달합니다.

웹에서는 계정 쿠키를 HttpOnly로 보관합니다. 모바일과 데스크톱에서는 기존 네이티브
쿠키 저장 경계를 유지합니다. 작업공간의 연결 구분값을 외부 브라우저에 전달해서
다른 브라우저의 계정을 대신하지 않습니다. 로그아웃이나 권한 변경 뒤에는 이전
응답과 스트림이 새 작업공간의 화면을 갱신하지 못하도록 확인합니다.

## 현재 검증 결과

2026-10-18 기준 증거의 범위는 다음과 같습니다. 서로 다른 소스 버전의 결과를
하나의 최신 전체 통과 결과로 합산하지 않습니다.

| 경로 | 확인한 결과 | 남은 범위 |
| --- | --- | --- |
| 실제 Supabase API | 서로 다른 작업공간의 같은 문서 ID 격리, 정규 리소스 요청, 작업공간·문서·감사 조회 | 노션 전체 제품과의 동등성 |
| 실제 웹 스트림 | 두 작업공간 자료 구분, 한쪽 수정의 격리, 해당 부모 로그인 종료 후 두 스트림 거절 | 모든 기기의 동시 종합 시나리오 |
| 공개 웹 배포 | 정적 자산 20개 해시 일치, 게시 HTML·CSP·범위, 예약 쿼리 112건 모두 404 | 실제 가족 계정의 최종 사용 검증 |
| macOS 앱 | 패키지 실행, 작업공간 전환·보류 편집의 선행 검증, 최신 게시 HTML 확인 | 모든 최신 변경을 포함한 전체 반복 검증 |
| Windows 앱 | 실행 파일·묶음·자산·압축 무결성 | Windows 운영체제에서 실제 실행 |
| iOS 앱 | 실제 Simulator 앱의 설정·로그인·첫 작업공간·문서 생성·네이티브 저장 | B 전환·복귀·종료 후 복구, 물리 iPhone 배포 |
| Android 앱 | 실제 Emulator 앱의 설정·로그인·첫 작업공간·문서 생성·네이티브 저장 | B 전환·복귀·종료 후 복구, 최종 배포 |

모바일에서는 A의 IndexedDB 미러가 남아 있는 상태에서 B 초기화의 기존 원본 보존
검사가 중단되는 문제를 실제 UI로 재현했습니다. A의 입력은 보존됐지만 이 결과는
정상적인 A→B→A 전환 성공을 증명하지 않습니다.

수정 계약은 실제 네이티브 로그인 범위별로 물리 미러 위치를 분리하는 것입니다.
기존 BASE 저장소를 지우지 않고, 이전 자료의 저장 확인·권한·복구 검사를 유지합니다.
새 로그인에서 이전 입력을 자동 전송하지 않으며, 같은 사용자의 이전 저장 위치는
제한된 복구 목록에서 찾을 수 있어야 합니다. 위치 정보는 저장 완료 확인이나
리소스 접근 권한을 대신하지 않습니다. 구체적인 DTO는
[공통 계약](../apps/mobile/tests/fixtures/native-mirror-contract.json)에 기록합니다.
이 계약의 검토 통과와 실제 구현·기기 검증의 완료는 구분합니다.

## 검증과 운영상 한계

정규 URL의 다국어·공백·물음표·해시·퍼센트 식별자는 실제 요청으로 확인했습니다.
일부 퍼센트 인코딩 별칭은 호스팅 경계에서 정규화된 뒤 앱에 전달됩니다. 앱에
도착한 잘못된 경로를 거절하는 검사를 유지하지만, 외부 원시 URL의 모든 별칭이
항상 400이 된다고 보장하지 않습니다. 확인한 별칭은 같은 자료를 반환했고 다른
작업공간의 연결을 사용한 요청은 거절됐습니다.

테스트 계정과 작업공간은 원래 사용자의 자료와 분리합니다. 기기 검증에 필요한
로그인과 미전송 입력이 남아 있는 동안 테스트 계정을 먼저 삭제하지 않습니다.
검증 종료 뒤 보호된 테스트 계정 표식·다른 자료 참조·실제 세션·파일·서버 작업을
확인하고 해당 범위만 정리합니다. 현재 정리는 완료되지 않았습니다.

구현 집계는 [기능 목록](rebuild/features.json)의 41개 영역 중 28개이며,
원본 전체와의 검증 완료율이 아닙니다. 외부 AI의 실제 응답, 기업용 연동,
서명 배포와 원본에서 관찰하지 못한 유료 기능은 별도의 남은 작업입니다.

재현 자료의 위치와 해시는 [증거 색인](research/multiworkspace-evidence.json)에
기록합니다. 로컬 비공개 자료는 Git에 포함하지 않습니다.
