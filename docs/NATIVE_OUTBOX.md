# 모바일 저장소 개발 상태

현재 배포용 모바일 설정은 `outboxVersion: 1`, `outboxEnabled: false`입니다.
OS SQLite에 저장하는 기반 코드를 기본 활성화하지 않습니다. 기존 WebView의
IndexedDB 캐시와 초안은 그대로 보존하며, 비활성 경로에서는 이관·초기화·복원을
실행하지 않습니다. 앱 화면은 미전송 내용을 **앱 캐시 보관**으로 표시합니다.
캐시를 지우거나 앱을 삭제하면 미전송 변경을 잃을 수 있으므로 서버 동기화나
복구 내용 내보내기를 먼저 완료해야 합니다.

서버에 저장한 문서와 데이터베이스는 같은 Fountain 계정으로 다시 받을 수
있습니다. 이 문서의 미전송 캐시 한계는 서버에 저장한 데이터와 별개입니다.

## 구현 경계

기존 실시간 문서의 ACK 처리는 canonical snapshot 저장과 확인된 대기 작업
삭제를 하나의 IndexedDB 트랜잭션으로 묶습니다. 선택된 저장 snapshot의
같은 epoch `state.seen`이 증명한 ID만 삭제합니다. 저장 실패 시 미전송 작업을
남기며, 메모리의 최신 상태만으로 디스크 저장을 추정하지 않습니다. 이 수정은
웹과 기존 모바일 캐시 경로에도 적용됩니다.

SQLite 기반은 iOS의 SQLite3, Android의 SQLiteDatabase를 사용하며 별도
SQLite 플러그인이나 새로운 인증 토큰을 추가하지 않습니다. OS 앱 전용 경로와
백업 제외를 사용하고, DELETE journal 및 EXTRA 동기화 설정을 확인합니다.
이는 앱 데이터의 별도 암호화나 물리적 완전 삭제를 보장한다는 의미가 아닙니다.
세션 쿠키와 자격 증명은 기존 네이티브 보안 저장소에만 남습니다.

검증용 어댑터는 다음 순서로 저장합니다.

1. 실제 IndexedDB 쓰기와 복구 intent를 같은 트랜잭션에 기록합니다.
2. 완료 후 변경분을 작은 조각으로 네이티브에 전송합니다.
3. SQLite COMMIT 성공 응답을 받은 뒤에만 호출자에게 저장 성공을 반환합니다.
4. 응답 유실 시 동일 txId와 digest로 receipt를 재확인합니다. 미확정 상태에서는
   후속 읽기와 쓰기를 차단합니다.

로그인 grant는 네이티브가 실제 관측한 `/api/session` 응답에서만 얻습니다.
공개 profile을 JS에서 저장하는 것으로 grant를 만들 수 없습니다. 서버 origin,
작업공간, 멤버, 로그인 binding을 구분하고, 이전 로그인·문서의 tombstone은
늦은 응답으로 지울 수 없습니다. 파일 전송 상태와 publication receipt는
같은 폐기 범위에 포함하며 실제 파일 바이트는 여기에 저장하지 않습니다.

## 활성화 전에 필요한 작업

기존 자료를 격리 보관하는 것만으로 안전한 이관이 끝나지 않습니다. 서버에서
새로 관측한 문서·데이터베이스 접근 증거, 명시적 격리 자료 승격, 로컬 새 페이지의
의존성 검증, 복구 화면, 로그인 뒤 lease/head 재동기화가 모두 필요합니다.
다른 로그인 binding의 자료를 자동 재전송하거나 이전 문서 snapshot을 그대로
활성 캐시로 승격해서는 안 됩니다.

실제 iOS/Android SDK 빌드와 기기 시험도 남아 있습니다. Chrome의 실제
IndexedDB 및 모의 bridge 시험, 일반 SQLite 또는 JDK 시험은 iOS 파일 보호,
Android 실제 connection 설정, Keychain/Keystore, OS 강제 종료·저장 공간 부족,
WebView 데이터 제거 뒤 복구의 기기 실행 증거를 대신하지 않습니다.
Xcode 라이선스 미확인과 Android SDK 미설치 상태를 우회하지 않습니다.

기본 설정을 켜기 전 이러한 조건을 충족하고, 기기에서 저장 확인·강제 종료·
재시작·로그아웃·계정 전환·캐시 제거를 실제 검증해야 합니다. 미확인 상태의
입력이 native COMMIT 전에 IndexedDB와 함께 사라지는 경우에는 복구할 수
없으며, 앱 삭제 뒤 로컬 자료 보존도 보장하지 않습니다.
