# 모바일 기기에 보관한 편집 복구

모바일의 **기기 저장과 동기화 → 앱 보관 내용 찾기**에서 이전 네이티브
저장 기록을 확인하고 파일로 보관할 수 있습니다. 복구를 지원하는 앱에서만
버튼이 표시됩니다. 부팅할 때 자동으로 저장소를 열거나 파일을 내보내지 않습니다.

현재 편집 중인 본문과 제목을 먼저 앱 캐시에 보관한 뒤 편집 화면을 일시
중지합니다. 저장이 실패하거나 한글 조합 중이면 복구 화면으로 넘어가지
않습니다. 확인을 마친 뒤 **앱 다시 열기**로 편집을 계속합니다.

## 사용 흐름

1. 같은 서버와 원래 기록을 작성한 계정으로 로그인합니다.
2. 기기 기록 목록에서 확인할 항목을 선택합니다.
3. 현재 서버 권한으로 내용을 확인하고, 보관 가능한 항목과 제외된 항목을 봅니다.
4. **파일로 보관**을 누르고 OS 저장 화면에서 위치를 정합니다.
5. 파일을 공통 편집기의 복구 JSON 가져오기로 열어 내용을 검토합니다.

가져온 편집은 새 식별자로 대기열에 보관됩니다. 서버에 반영하려면 기존
복구 확인·다시 적용 절차를 거쳐야 합니다. 내보내기나 가져오기만으로 과거
작업을 자동 전송하지 않습니다. 여러 파일 중 저장을 취소하면 이미 저장한
파일 수를 안내하며 원본 기록은 그대로 남습니다.

## 보존과 접근 범위

기존 SQLite 파일만 읽기 전용으로 엽니다. 파일이 없으면 만들지 않으며,
기록·head·lease·receipt·원본 스키마를 수정하지 않습니다. 복구 중 로그인,
계정 전환, 취소도 원본 SQL을 지우지 않습니다. 다른 계정의 제목·본문·건수는
목록에 나타나지 않습니다.

현재 로그인과 문서·DB·행·첨부·관계 참조의 접근은 네이티브 HTTPS 응답으로
다시 확인합니다. 화면이 전달한 profile이나 과거 권한 정보는 허가로 쓰지
않습니다. 현재 편집 권한을 확인할 수 없거나 로컬 새 페이지의 의존 관계를
증명할 수 없는 기록은 제외하고 원본에 남깁니다.

목록과 확인 결과에는 임시 식별자·종류·건수·파일 크기만 전달합니다. 원본
본문, SQLite 경로, 쿠키와 서버 비밀은 복구 브리지로 화면에 반환하지 않습니다.
파일에는 허용한 편집·본문 필드만 넣으며 과거 ACL·소유자·로그인·수신 확인
정보를 복사하지 않습니다. 계정·서버·원본 파일·권한이 바뀌면 다시 확인해야 합니다.

일반 영구 outbox는 계속 `outboxEnabled:false`입니다. 별도
`recoveryVersion:1, recoveryEnabled:true`만 명시적 읽기 복구를 허용합니다.
일반 인증 만료·재로그인 때 미전송 캐시를 보존하는 정책, 로컬 의존 관계의
완전한 복구, 안전한 자동 동기화 재개는 추가 작업입니다. 앱 삭제 뒤 로컬
기록 보존과 WebView 캐시 퇴거 뒤 모든 편집 복구를 보장하지 않습니다.

## 파일과 기술 한도

기본 출력은 기존 `fountain-recovery-v2` JSON입니다. 파일 하나에 원래 로그인
범위 하나만 담습니다. 선택은 최대 100개, 준비한 파일 합계는 64MiB,
개별 파일과 원본 레코드는 16MiB입니다. 레코드 1,000개·본문 블록 2,000개 등
기존 가져오기 한도를 함께 검사합니다. 원본 레코드 하나씩 읽고 파일 쓰기는
최대 256KiB 조각으로 처리합니다.

허용된 내용이 일반 복구 파일 한도를 넘으면 순서와 해시가 있는 읽기용 JSON
조각으로 보관할 수 있습니다. 내용을 자르거나 일부 의존 작업만 자동 실행하지
않으며, 이 경우 사람이 내용을 확인해 나누어 복구해야 한다고 안내합니다.
일반 `saveData` 브리지의 8MiB 한도는 그대로입니다.

## 검증

```sh
npm run --prefix apps/mobile test:recovery
```

이 명령은 Chrome 화면·실제 임시 HTTP 서버·IndexedDB와 SQLite 복구 모델을
검사합니다. 원본 해시 보존, 현재 계정과 권한, 큰 Unicode 내용의 조각 복원,
현재 가져오기로 미리보기·대기 보관·명시 적용을 검증합니다. OS 파일 선택기,
실제 모바일 TLS와 네이티브 저장소의 증거는 플랫폼 SDK 검사와 구분합니다.

플랫폼별 실제 실행 결과와 남은 범위는 [모바일 안내](../apps/mobile/README.md),
기본 비활성 저장소의 조건은 [저장소 상태](NATIVE_OUTBOX.md)를 참고합니다.
