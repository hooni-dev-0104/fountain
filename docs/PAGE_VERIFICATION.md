# 페이지 검증

페이지의 내용을 확인한 담당자와 유효 기간을 기록한다. **페이지 메뉴 → 페이지 검증** 또는 제목 아래의 **검증 설정**에서 여러 담당자를 선택하고, 만료 없음이나 만료 날짜·시간을 정한다. 이미 검증된 페이지는 같은 창에서 갱신하거나 해제한다.

현재 열람할 수 있는 페이지와 DB 행의 검증을 모아 보려면 [설정 → 검증된 페이지](VERIFIED_PAGES.md)를 사용한다. 목록에서 문서를 연 뒤 기존 검증 화면으로 이동하며 변경 권한은 그대로 적용한다.

문서 편집 이상 권한이 필요하다. 담당자 지정은 페이지의 소유자나 공유 권한을 바꾸지 않으며, 이 페이지를 볼 수 있는 활성 구성원만 지정할 수 있다. 방문자는 본인에게 공개된 멤버만 선택할 수 있다. 숨겨진 담당자의 이름·ID·인원 수는 노출하지 않는다.

유효 기간이 지나면 **검증 만료**로 표시하고, 잘못 저장된 이전 정보는 **검증 상태 확인 필요**로 표시한다. 이 표시는 원본 문서를 수정하거나 알림 메일을 보내지 않는다. 담당자 정보가 비공개인 정상 검증은 유효 기간과 상태를 유지한다. 담당자는 [알림함](INBOX.md)에서 현재 만료된 검증과 개인 읽음·보관 상태를 확인한다. [위키](WIKI.md) 자식 문서는 지식 담당자이면서 편집 권한이 있어야 검증할 수 있다. 데이터베이스 행은 별도 [담당자·검증 속성](DATABASE_VERIFICATION.md)을 사용한다. 배경 전달·이메일은 아직 미완료다.

날짜 입력은 화면에 표시한 기기 시간대를 기준으로 한다. 존재하지 않는 현지 시각이나 과거 만료일은 저장하지 않는다. 기존 만료값을 바꾸지 않으면 원래 시간대와 소수 초를 보존한다.

저장하는 동안 문서·계정·권한·편집 기준이 바뀌면 다른 화면에 결과를 적용하지 않는다. 다른 변경이 먼저 저장됐다면 입력을 남기고 충돌을 안내한다. 최신 내용을 확인한 뒤 창을 다시 열어 검증한다. 검증은 서버 연결이 필요한 작업이며 오프라인에서 자동 대기열에 넣지 않는다.

## API

`POST /api/pages/{id}/verify`

```json
{
  "owners": ["현재 페이지를 볼 수 있는 멤버 ID"],
  "expires_at": null,
  "revision": 7
}
```

`owners`는 중복 제거 후 1~1,000명이다. 이는 요청 처리의 기술적 한도다. 이전 호출자의 단일 `owner` 입력도 지원하지만 `owners`와 함께 보내면 거절한다. 담당자 생략은 실제 요청자를 사용한다. 무기한은 만료값의 생략 또는 `null`로만 표현하며, 날짜는 시간대를 포함한 미래 RFC3339 시각을 사용한다. `false`, 빈 문자열, 배열 등은 유효한 만료값이 아니다.

`DELETE /api/pages/{id}/verify`에는 `{"revision":7}`을 보낸다. 두 메서드는 편집 이상 권한을 검사하고 페이지 revision을 증가시킨다. 현재 화면은 검토한 revision을 항상 보내며, 오래된 값은 409로 거절한다. 이전 API 호출과의 호환을 위해 revision 생략도 지원한다.

응답의 `verification`에는 담당자 목록 `owners`, 이전 형식의 첫 담당자 `owner`, 실제 검증자 `verified_by`, 검증 시각 `verified_at`, 만료 시각 `expires_at`이 있다. 현재 요청자에게 숨겨진 ID는 제거한다. 보이는 담당자를 수정할 때 기존의 숨겨진 유효한 담당자는 보존하며, 명시적인 검증 해제는 전체 검증 정보를 지운다. 변경 응답 뒤에는 현재 문서·로그인 범위의 공동 편집 정본을 다시 읽는다.

## 조사·검증 범위

[Notion 공식 안내](https://www.notion.com/help/wikis-and-verified-pages)의 일반 페이지 검증, 여러 담당자, 기한 설정과 해제 동작을 참고했다. Notion의 내부 구현을 복원하거나 전체 위키·DB 속성·메일 통합까지 완료했다고 주장하지 않는다.

Python·TypeScript의 권한·만료·충돌 처리와 실제 임시 SQLite/Chrome 화면을 검증했다. 별도 Supabase 공간에서는 실제 계정, 원본 레거시 정보 보존, 현재 권한과 1,000명 지정을 확인했다. 실행 증거와 플랫폼별 한계는 [실행 기록](research/page-verification-evidence.json)에 기록한다. TypeScript 정적 타입 검사는 별도 컴파일러가 없어 아직 수행하지 않았다.
