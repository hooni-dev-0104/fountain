# 복구 JSON 가져오기

**기기 저장과 동기화 → 복구 JSON 가져오기**에서 이전에 내려받은 파일을 선택합니다.
현재 서버의 문서·DB·권한·첨부 정보를 확인한 미리보기를 보고, **확인하고 복구
대기열에 가져오기**를 누릅니다. 파일 선택이나 미리보기만으로 서버의 문서·DB와
변경 대기열을 수정하지 않습니다.

가져온 행·문서 변경은 `paused` 상태로 보관합니다. **현재 값 기준으로 다시 적용**을
눌러야 새 작업 ID와 현재 기준 값을 사용해 동기화합니다. 본문은 선택한 문서의
**보관된 편집 내용**에 보관하며, **복구 내용을 새 블록으로 추가**를 별도로 눌러야
본문에 합쳐집니다. 현재 문서 전체를 덮어쓰는 동작이 아닙니다.

## 지원 자료와 출처

- 기존 `fountain-mutation-recovery-v1`: 행 생성·수정·삭제, 문서 생성·제목 등
  메타데이터, 새 문서의 본문·미전송 편집과 복구 초안.
- 새 `fountain-recovery-v2`: 서버·작업공간·멤버·원래 로그인 binding을 명시하고,
  같은 변경과 본문 복구 초안을 함께 내보냅니다.
- 기존 형식 없는 본문 복구 JSON: 현재 편집 가능한 목적지 문서를 선택하고
  새로운 복구 내용으로 복사합니다. 이 파일만으로 원래 계정을 인증하지 않습니다.

형식에 출처가 있는 파일은 같은 원본 서버·작업공간·멤버에서 가져옵니다.
같은 계정의 이전 로그인 binding은 허용합니다. 다른 계정이나 다른 서버의
복구 파일을 현재 큐로 자동 연결하지 않습니다. JSON의 출처 표기와 SHA256은
전자 서명이나 로그인 수단이 아니며, 실제 현재 세션과 서버 권한을 별도로 확인합니다.

새 문서·새 항목·본문의 식별자는 새로 만듭니다. 새 부모·자식 문서, 행의 부모·
선행 작업 및 스키마가 지정한 relation 참조는 함께 다시 연결합니다. 기존 자료를
수정·삭제하는 작업은 현재 존재와 권한을 확인합니다. 파일의 과거 `applied`
상태나 영수증으로 성공·권한을 추정하거나 이전 연산 ID를 그대로 실행하지 않습니다.

새 문서 사본은 가져온 공유 권한을 사용하지 않고 고정 비공개 ACL로 준비합니다.
서버의 기존 소유자·워크스페이스 관리자 정책은 유지합니다. 필요하면 복구와
확인 후 앱의 일반 공유 기능으로 접근 권한을 정합니다. 기존 문서·DB에 대한
수정은 해당 자료의 현재 권한을 바꾸지 않습니다.

## 본문과 첨부

같은 epoch의 본문과 미전송 연산을 함께 해석하고 새 연산으로 다시 구성합니다.
여러 탭의 편집을 가장 최근 초안 하나로 대체하지 않습니다. 원래 문자 위치나
이전 epoch의 의미를 확정할 수 없으면 원문 작업 JSON을 읽을 수 있는 코드
블록으로 보존하고 미리보기에서 안내합니다. 이것은 원래 문서 화면의 정확한
재현이 아니며, 불확실한 옛 작업을 현재 문서에 그대로 재전송하지 않습니다.

파일 전체의 자동 RGA 복원·본문 구성은 50,000 구성 비용 예산 안에서 실행합니다.
문자 수에 더해 공개 이력·삽입·삭제·서식 후보의 확장 비용을 합산합니다.
작은 파일의 큰 삽입 문자열이나 공개 이력의 문자 수가 객체로 무제한 확장되지
않도록 구성 비용도 확인합니다. 예산을 넘는 새 문서 본문은 자동으로 적용하지
않고 읽을 수 있는 복구 초안과 원문 JSON으로 보존하며 미리보기에서 알립니다.
한 번에 본문으로 추가할 수 있는 양은 50,000코드포인트, 현재 본문과 합계는
100,000코드포인트입니다. 초과하면 현재 문서와 초안을 유지하므로 원문을
내려받아 나누어 복구할 수 있습니다. 일반 문서 편집에 추가한 전역 제한은 아닙니다.

첨부는 `GET /api/attachments/:id/metadata`로 현재 접근·이름·크기 등을 확인합니다.
미리보기에는 외부 이미지나 파일 다운로드 링크를 자동 실행하지 않습니다.
복구 JSON은 파일 바이트의 백업이 아니므로, 원본 서버에 없거나 현재 권한이
없는 첨부를 이 파일만으로 재생성하지 않습니다.

## 중복·실패와 한계

같은 로그인에서 같은 정규화 내용은 한 번 보관합니다. 본문 복구는 목적지
문서도 중복 판정에 포함하므로, 다른 문서를 명시적으로 선택한 복사는 별개입니다.
이 영수증은 기기의 현재 로그인 저장소에 있는 자료이며 다른 기기·로그인까지
전역으로 중복을 막는 기능은 아닙니다.

가져오기 작업과 영수증은 하나의 IndexedDB 트랜잭션으로 저장합니다. 중간
오류·용량 부족·계정 전환·미리보기 취소는 불완전한 작업 묶음을 남기지 않습니다.
기존 초안·기존 작업을 덮거나 원본 파일을 지우지 않습니다. 확인 전에 서버의
내용·스키마·권한·삭제 하위 범위가 달라지면 미리보기를 다시 열어야 합니다.
실제 재적용 시에도 서버의 현재 권한·이전 값·하위 항목 검사를 적용합니다.

파일은 최대 16MiB, 변경은 1,000개, 본문은 합쳐서 2,000블록입니다. JSON 파싱
전 중첩·구조 수를 확인하고 이후 내용·참조 그래프·문자열을 검증합니다. 서로
맞지 않는 출처·중복 ID·순환 의존·지원하지 않는 값은 거절하며 원본 파일은
그대로 남습니다. 본문 추가 시에는 현재 문서와 합친 2,000블록 한도를 다시 확인합니다.

웹 공통 코드와 모바일 번들에 같은 화면을 사용합니다. 현재 모바일의 일반
저장 경로는 WebView 캐시이고 [SQLite 기반은 비활성](NATIVE_OUTBOX.md)입니다.
이 가져오기 기능이 OS 저장소 퇴거·앱 삭제 뒤의 영구 복구나 실제 iOS/Android
SDK 실행을 검증했다는 의미는 아닙니다.

검증 명령:

```sh
node tests/recovery-import.mjs
node tests/browser-recovery-storage.mjs
node tests/browser-recovery-core.mjs
node tests/browser-recovery-import.mjs
python3 -m unittest tests.test_attachment_metadata
```
