# 워크스페이스 검색

검색창에서 접근할 수 있는 페이지·데이터베이스·행을 함께 찾습니다. 여러 단어는 모두 일치해야 하며, `"가족 여행"`처럼 큰따옴표로 묶으면 연속된 구절을 찾습니다. 한글과 Unicode 정규화·대소문자 접기를 지원하는 문자열 검색입니다. AI 답변이나 의미 검색, 외부 앱 색인은 연결하지 않았습니다.

필터 버튼으로 유형·제목만·소유자·팀스페이스·상위 페이지·생성일/수정일을 선택합니다. 날짜는 기기의 현지 날짜를 기준으로 하며, 종료일도 포함합니다. 정렬은 관련도·최근/오래된 수정일·최근/오래된 생성일·제목순입니다. 결과는 20개씩 더 볼 수 있습니다.

페이지 범위는 저장된 `parent_id`/`page_id` 연결과 접근할 수 있는 상위 페이지를 기준으로 합니다. 연결 정보가 없는 DB와 그 행은 특정 페이지의 하위 범위에 포함하지 않습니다. 행 결과를 누르면 DB를 새로 읽고 그 행이 여전히 보이는 경우에만 상세 화면을 엽니다.

검색은 권한 검사 뒤에 개수·순위·미리보기를 계산합니다. 보관된 항목, 파일/임베드 블록, 사람·파일·관계·수식·롤업·알 수 없는 중첩 속성은 검색 대상에서 제외합니다. 날짜 범위 속성은 정확한 유효 시작/종료 값만 읽습니다. 감사 로그에는 결과 개수와 검색 방식만 기록하며 검색어와 원문은 남기지 않습니다.

목록이 바뀌면 더 보기를 중단하고 처음부터 다시 검색하도록 안내합니다. 권한 거절은 기존 결과를 지우며 구형 검색이나 캐시로 대체하지 않습니다. 오프라인에서는 기기에 보관된 페이지·DB 제목만 검색하고 필터는 끕니다. 구형 서버는 지원 여부 확인 후 페이지 검색만 제공합니다.

## API

`GET /api/search/advanced`와 `HEAD`를 제공합니다. 기존 `GET /api/search`의 페이지 검색 계약은 유지합니다. 로그인 후 `/api/capabilities`의 `search_advanced:true`로 지원 여부를 확인합니다.

- `q`: 최대 500 Unicode 문자, 최대 16개 단어/구절.
- `types`: `page,database,row` 중 중복 없는 유형. 기본은 모두.
- `owner`: 반복 가능, 중복을 제외하고 최대 20명. 나머지 매개변수는 반복할 수 없습니다.
- `teamspace`, `in`: 각각 한 개의 접근 가능한 팀스페이스·상위 페이지 ID.
- `title_only`: `0|1`. `date_field`: `updated|created`.
- `after`, `before`: `YYYY-MM-DDTHH:mm:ss.sssZ`. 시작 이상·종료 미만.
- `sort`: `relevance|updated_desc|updated_asc|created_desc|created_asc|title`.
- `limit`: 1–50, 기본 20. `offset`: 0–100000, 기본 0.
- `result_set`: 이전 응답의 SHA256 표시자. `offset>0`이면 필수이며 권한을 부여하지 않습니다. 매 요청의 현재 권한과 결과로 다시 계산합니다. 변경되면 409입니다.

응답은 `results,total,offset,limit,has_more,next_offset,result_set`입니다. 개별 결과는 `type,id,title,icon,snippet,owner_id,created_at,updated_at`만 포함하며, 행에는 `database_id,database_title`이 추가됩니다. 블록·원시 속성·ACL·인증 정보는 포함하지 않습니다.

실행 증거와 실제 클라우드·브라우저·네이티브 검증의 구분은 [검증 기록](research/advanced-search-verification.md)을 참고하세요.
