# 검증된 페이지 목록

**설정 → 검증된 페이지**에서 현재 열람할 수 있는 검증 문서를 모아 본다. 일반 페이지·위키 페이지·데이터베이스 행 중 **검증됨** 또는 **검증 만료** 상태인 항목을 표시한다. 미검증·잘못된 검증 정보·보관/삭제된 항목은 포함하지 않는다. 일반 멤버와 게스트는 **내 계정 → 검증된 페이지**에서도 열 수 있다. 이 목록을 열어도 다른 관리자 설정 권한은 추가되지 않는다.

제목 검색과 담당자·팀스페이스·검증 상태·문서 종류 필터를 사용한다. 화면은 한 번에 50개를 보여 주며 **이전 / 다음**, **초기화**, **새로고침**을 제공한다. 결과에는 제목·종류·공개 담당자·팀스페이스·검증 시각·만료일을 표시한다. 보이는 담당자가 없으면 **담당자 정보 비공개**, 위치를 공개할 수 없으면 **위치 정보 비공개**로 표시한다.

**열기**는 기존 문서나 행의 상세 화면으로 이동한다. **검증 보기**는 최신 원본을 읽은 뒤 기존 검증 화면을 연다. 변경에는 [페이지 검증](PAGE_VERIFICATION.md)·[위키](WIKI.md)·[DB 검증](DATABASE_VERIFICATION.md)의 현재 편집 권한·담당자·잠금·충돌 규칙을 적용한다. 목록의 표시값을 수정 기준으로 재사용하지 않으며, 삭제되거나 접근할 수 없게 된 행을 새 행 입력창으로 열지 않는다. 목록 안에서 일괄 검증·담당자 변경·해제는 지원하지 않는다.

## 공개 범위와 위치

소유자·관리자·멤버·게스트 모두 **현재 자신이 읽을 수 있는 항목**만 조회한다. 지식 담당자 지정은 공유 권한을 추가하지 않는다. 권한과 공개 담당자를 먼저 판정한 뒤 검색·필터·개수·페이지 나누기를 적용한다. 담당자와 팀스페이스 선택지는 읽을 수 있는 전체 검증 후보의 공개 값에서 만들며, 현재 검색 필터를 적용하기 전의 선택지다. 숨겨진 담당자·상위 문서·데이터베이스의 이름이나 임의 속성을 목록에 덧붙이지 않는다.

팀스페이스는 현재 문서 계층의 최상위 페이지에서 결정한다. 상위 페이지가 없는 문서는 자신의 팀스페이스를, 페이지 아래 데이터베이스의 행은 그 데이터베이스가 속한 최상위 페이지의 팀스페이스를 따른다. 상위 페이지가 없는 데이터베이스는 자신의 팀스페이스를 사용한다. 이동 전에 자식에 남아 있던 팀스페이스 값으로 위치를 추정하지 않는다.

상위 경로 누락·잘못된 ID·순환·64개 연결 초과 또는 팀스페이스 자체의 열람 불가 시 위치는 `null`이다. 위치를 알 수 없어도 항목 자체를 읽을 권한이 있으면 목록에 표시할 수 있다. 이 위치 계산은 공유 권한 판정을 대체하지 않는다.

## API

`GET /api/verified-pages`와 같은 경로의 HEAD를 지원한다. 변경 요청과 추가 경로는 지원하지 않는다.

| 쿼리 | 의미와 한도 |
| --- | --- |
| `q` | 제목의 문자 그대로 부분 검색. 최대 200개 Unicode 코드 포인트, 기본값 빈 문자열. NFKC·대소문자·공백을 정규화하며 NUL과 잘못된 surrogate를 거절한다. |
| `owner`, `teamspace` | 공개 담당자·팀스페이스 ID. 생략하면 전체이며 빈 값이나 특별한 전체 선택 ID를 보내지 않는다. |
| `status` | `all`·`verified`·`expired`, 기본값 `all`. |
| `kind` | `all`·`page`·`row`, 기본값 `all`. |
| `limit`, `offset` | 각각 1~100·0~1,000,000의 정수. 기본값 50·0이며 부호·불필요한 앞자리 0·소수 표기를 허용하지 않는다. |

알 수 없는 쿼리와 중복 쿼리는 400이다. 형식이 올바르지만 존재하지 않거나 공개되지 않은 담당자·팀스페이스 ID는 빈 결과를 반환하여 존재 여부를 알려 주지 않는다. 결과는 정규화한 제목, `resource_type`, ID 순으로 정렬하며 로캘별 정렬 규칙을 사용하지 않는다.

응답은 `items`, `total`, `has_more`, `limit`, `offset`, `filters`다. `filters`의 `owners`·`teamspaces`는 각각 `{id,name}` 목록이다. 항목에는 `id`, `resource_type`, `title`, `icon`, `owners:[{id,name}]`, `teamspace:{id,name}|null`, `verification:{status,verified_at,expires_at}`가 있다. 페이지는 `page_id`, 행은 `database_id`·`row_id`를 추가한다. 행 제목은 첫 제목 속성을 사용한다. 원본 속성·ACL·생성자·비공개 검증 회차·세대·변경용 revision은 포함하지 않는다.

## 연결과 저장

이 목록은 서버 연결이 필요하다. 검색 결과를 오프라인 캐시나 변경 대기열에 저장하지 않는다. 창 닫기·탭/계정 전환·로그아웃·네이티브 복구 점검·오프라인 전환 시 표시 자료를 지우고 이전 응답을 적용하지 않는다. 검색 조건을 바꾸면 첫 페이지부터 읽으며 실패한 페이지의 자리에 이전 결과를 남기지 않는다. 기존 문서·행의 작성 중인 입력은 해당 편집기의 이동·저장 규칙을 따른다.

조회는 문서·행의 검증 상태나 [알림함](INBOX.md)의 읽음·보관을 바꾸지 않는다. 현재 상태를 읽는 목록이므로 과거 만료 사건 기록·배경 전달·이메일/푸시는 제공하지 않는다. 클라우드에서는 기존 페이지 헤더와 DB 검증 메타데이터를 재사용하며 관계없는 문서·DB·행의 일반 속성 본문으로 대체 조회하지 않는다. 기존 응답·트랜잭션 용량 한도는 유지한다.

## 근거와 남은 범위

[Notion 공식 안내](https://www.notion.com/help/wikis-and-verified-pages)에서 **Settings → Verified pages**, 특정 페이지 검색, 담당자·팀스페이스 필터를 확인했다. 역할별 접근 정책, 추가 상태/종류 필터, 정렬·페이지 나누기·계층 위치 규칙과 API는 Fountain의 독립 설계다. Notion의 실제 유료 계정 화면과 모든 관리 기능을 대조하거나 비공개 서버를 복원한 결과가 아니다. 기존 [REA 조사](research/notion-desktop.md)의 근거도 선택한 클라이언트 파일에 한정된다.

API 20의 46개 파일을 배포 후 소스와 대조했다. 실제 Supabase의 두 계정·담당자 1,000명, 약 163.5MB 원본의 본문 없는 목록과 원문 보존, Chrome의 실제 로그인·필터·행/읽기 전용 페이지 열기·로그아웃을 확인했다. 대용량 원본 검사를 마친 뒤 해당 큰 시험 자료만 제거하고 화면 검사를 수행했으며 전체 163MB 작업공간의 화면 초기화를 검증한 것은 아니다. 테스트 계정·세션·자료는 정리했다. [실행 증거와 설치 범위](research/verified-pages-evidence.json)를 참고한다. 모든 유료 기능 동등성, 일괄 관리, 배경 알림과 실사용 가족 계정의 다섯 플랫폼 전체 여정은 이 목록 구현으로 완료되지 않는다.
