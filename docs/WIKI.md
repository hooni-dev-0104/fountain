# 위키

독립된 일반 페이지에서 **페이지 메뉴 → 위키로 전환**을 선택한다. 해당 페이지의 전체 권한이 필요하며 잠긴 페이지·삭제된 페이지·하위 페이지·데이터베이스는 전환할 수 없다. **위키 해제**는 문서의 본문·하위 페이지·공유 권한·검증 기록을 유지한다. 위키 루트는 다른 페이지 밑으로 이동할 수 없다.

위키에는 **홈**, **모든 페이지**, **내 담당 페이지** 보기가 있다. 홈에서는 기존 본문을 그대로 편집한다. 다른 탭으로 이동해도 편집기와 보류 중인 입력을 유지한다. 목록에서 검색·새로고침·더 보기를 사용하고 제목을 눌러 문서를 연다. 내 담당 페이지는 현재 로그인한 사용자가 지식 담당자인 문서다. 현재 열람할 수 없는 문서는 제목과 개수에 포함하지 않는다.

위키 안에서 새로 만든 문서는 서버가 확인한 실제 생성자를 지식 담당자로 기록한다. 기존 문서를 편입한 경우에는 유효한 기존 문서 소유자를 기본 담당자로 사용한다. 이 기본값은 과거 작성자를 복원했다는 의미가 아니다. 문서 상단의 **지식 담당자**에서 편집 권한이 있는 사용자가 담당자를 바꿀 수 있다. 유효한 활성 구성원 중 그 문서를 볼 수 있는 사람만 선택할 수 있다.

**지식 담당자 지정은 공유 권한을 추가하지 않는다.** 위키 자식 문서는 지식 담당자이면서 편집 권한이 있는 사용자가 검증한다. 담당자를 바꾸면 유효한 기존 검증의 담당자를 바꾸되 검증 시각·만료일·실제 검증자는 보존한다. 잘못 저장된 이전 검증 정보를 담당자 변경으로 정상 정보처럼 바꾸지는 않는다. 일반 페이지와 위키 홈의 기존 다중 담당자 검증은 유지한다.

하위 문서만 직접 공유받은 사람에게 비공개 위키 루트의 이름·ID를 표시하지 않는다. 게스트에게는 다른 구성원의 담당자 정보도 제한한다. 역할·담당자·위키 계층은 서버에서 다시 검사하므로 오래된 화면의 권한 표시로 변경을 강제할 수 없다.

위키 전환·해제·담당자 변경·목록 조회는 서버 연결이 필요하다. 해당 변경은 오프라인 대기열에 넣지 않는다. 캐시된 본문 편집은 기존 문서 저장·복구 정책을 따르며, 권한이 읽기 전용으로 바뀌었을 때 보류 본문은 복구 초안으로 보존한다. 계정 전환·접근 철회·기기 보관 점검 시에는 위키 목록과 담당자 창을 닫고 다른 화면에 늦은 응답을 적용하지 않는다.

## API

- `POST /api/pages/{id}/wiki`, `DELETE /api/pages/{id}/wiki`: `{"revision":7}`. 현재 revision을 반드시 보내며 오래된 값은 409, 잠금은 423이다.
- `GET /api/pages/{root}/wiki?view=all&q=&limit=50&offset=0`: `home`, `all`, `owned` 보기. 검색은 최대 200자, limit은 1~100, offset은 0~1,000,000이다. 알 수 없는 필드·중복·잘못된 숫자는 거절한다.
- `GET /api/pages/{id}/wiki-owner`: 현재 권한으로 담당자와 선택 가능한 구성원을 읽는다. 읽을 수 있는 일반 페이지·위키 홈은 `in_wiki:false`, 위키 자식은 `in_wiki:true`다. 비공개 루트는 `wiki:null`이다. 404는 일반 페이지라는 판정에 사용하면 안 된다.
- `PATCH /api/pages/{id}/wiki-owner`: `{"owner_id":"구성원 ID","revision":7}`. 문서 revision을 증가시키며 실제 ACL 소유자·본문·접근 권한 세대는 바꾸지 않는다.

일반 페이지 생성·수정 요청으로 위키 여부나 담당자를 위조할 수 없다. 위키 소속은 현재 상위 페이지 경로로 판단한다. 기본 담당자는 서버가 생성 시 고정한 문서 소유자를 사용하고, 명시적인 담당자 변경은 비공개 `wiki_page` 기록에 저장한다. 위키 조회는 문서·설정·담당자 상태를 변경하지 않으며 기존 인증·트랜잭션 내부 승인 기록은 생성될 수 있다. JSON 가져오기는 일반 비공개 문서를 만들므로 위키 설정과 담당자의 JSON 왕복 복원을 의미하지 않는다.

클라우드의 위키·담당자·검증 권한 조회에는 실제 페이지에서 계산한 16개 필드의 내부 메타데이터를 사용한다. 관계없는 문서의 본문·표지·임의 필드는 가져오지 않으며, 변경할 때는 대상 문서의 실제 본문을 읽어 보존한다. 저장된 동명 메타데이터로 이 정보를 위조할 수 없다. 기존 응답·트랜잭션 용량과 계층 권한 한도는 유지하므로 무제한 크기의 작업공간을 보장하지 않는다.

## 근거와 남은 범위

[Notion 공식 안내](https://www.notion.com/help/wikis-and-verified-pages)의 독립 페이지 전환·해제, 세 기본 보기, 생성자 기본 담당자, 담당자 변경과 검증 동작을 참고했다. 기존 [REA 조사](research/notion-desktop.md)는 설치된 클라이언트 일부를 분석한 증거이며 비공개 위키 서버를 복원한 결과가 아니다. 담당자를 공유 권한과 분리한 저장 방식, 기존 문서의 기본값과 API는 Fountain의 독립 설계다.

현재는 기본 보기와 담당자·검증 연결을 구현했다. 일반 데이터베이스의 [담당자·Verification 속성](DATABASE_VERIFICATION.md)은 별도 경로로 구현했다. 사용자 지정 위키 DB 속성·추가 레이아웃·블록을 이용한 페이지 분류/끌기, 위키 목록 안에서 직접 담당자·검증을 바꾸는 편집기, 배경 만료 전달·이메일/푸시는 남아 있다. 실제 Windows·물리 모바일 기기와 다섯 플랫폼의 실사용 가족 계정 전체 여정도 별도 검증이 필요하다. 자세한 위키 실행 범위는 [검증 기록](research/wiki-evidence.json)에 남긴다.
