# 통합 검색 검증 — 2026-10-17

Supabase API **11**에 페이지·DB·행 통합 문자열 검색을 반영했다. 문자열/구절·유형·소유자·팀스페이스·실제 상위 페이지 연결·생성/수정일·정렬·페이지 나눔을 제공한다. 기존 페이지 검색 API는 유지한다. [사용 방법](../SEARCH.md), [구조화된 증거](advanced-search-verification.json).

이 기능은 Notion의 비공개 서버 복원이 아닌 독립 구현이다. 공개 검색 명세는 [Notion 검색 도움말](https://www.notion.com/help/search)을 참고했다. 원래 REA 조사 범위는 [조사 기록](notion-rea.md)에 유지한다. [Supabase 내장 gte-small](https://supabase.com/docs/guides/functions/ai-models)은 영어용이므로 한국어 의미 검색으로 사용하지 않았다. 외부 앱 색인·생성형 AI·Gemini Pro 구독 연결을 완료했다는 의미가 아니다.

## 실제 클라우드

원본과 분리한 새 QA 공간에 비업무 fixture 16개를 넣고, 실제 GoTrue 소유자 부트스트랩과 멤버 계정 생성·로그인을 수행했다. 가짜 Auth 행이나 서비스 키를 브라우저에 주입하지 않았다. 고정 프로젝트·작업공간·보호 nonce·내부 경로·RPC를 제한한 검증용 함수 53에서 실제 API를 호출했다. 이 함수는 새로운 권한 경로가 아니라 기존 앱의 실제 인증/트랜잭션을 실행하는 봉인된 테스트 진입점이다.

- 멤버에게 페이지·DB·행 **6개**가 보였고, 비공개 자료는 개수·순위·미리보기에 반영되지 않았다. 실제 멤버 역할을 admin/guest/member로 바꾸어 관리자에게 비공개 권한이 자동 부여되지 않으며 게스트 결과가 0개가 됨을 확인했다.
- 한글 본문·따옴표 구절·제목만·유형·소유자·하위 페이지·6개 정렬·더 보기·HEAD·잘못된 입력 400·구형 검색 계약을 확인했다. 담당 행 제한도 적용됐다.
- 파일/첨부 블록·사람·파일·관계·수식·알 수 없는 속성·휴지통 자료의 고유 문자열은 결과 수가 0이었다. 원시 블록·속성·ACL을 DTO로 반환하지 않는다.
- 검색 감사 쓰기 사이에는 같은 표시자로 다음 쪽을 읽었다. 실제 페이지 권한을 철회하면 결과가 **5개**, 실제 행을 삭제하면 **4개**가 되며 기존 표시자는 409였다. 표시자는 매번 현재 권한으로 다시 계산하며 권한 증명이 아니다.
- 실제 검색 감사 기록 **31개**의 details에 개수·검색 방식 외 필드가 없음을 SQL로 확인했다. 부적절한 매개변수의 StoreProvider 호출 0은 별도 메모리 HTTP 경계 테스트 증거다.

실제 Storage 파일 전송이나 네이티브 앱의 검색 화면 실행은 이번 검증에 포함하지 않았다. 코드와 공유 모듈 40개가 검증용 배포와 일치하는 것을 확인한 뒤 API 11을 배포했다.

## 소스·브라우저

- 최종 Node 전체 **383 PASS, 실패/skip 0**, 49.522초. Python/SQLite와 5개 역할·Unicode·날짜·필터·정렬·오류의 결과/표시자 **360건 일치**를 포함한다.
- Python 전체 **497건 중 425 PASS, 72 skip**, 64.501초. 이번 실행에는 선택적 PostgreSQL DSN을 넣지 않았다. 과거 PostgreSQL 실행 결과를 이번 전체 실행으로 세지 않는다.
- 별도의 실제 임시 Python 서버와 Chrome에서 3개 결과 유형·필터·20→25개 더 보기·실제 목록 변경 409·행 열기·삭제된 행·HTML 이스케이프를 확인했다. 기존 transport 회귀도 통과했다.
- 늦은 이전 query/모달/계정·전송 세대, 같은 DB의 새 조회 403, 더 보기 403/404는 명시적 HTTP/전송 오류 주입이다. 거절 뒤 결과·DOM·marker·offset을 지우며 구형 검색/캐시로 우회하지 않는다. 실제 계정 전환과 실제 network-offline 제목 표시를 함께 확인했다.
- 1280px/390px 실제 화면을 직접 검토했고 시각 판정 **94 PASS**였다. 웹·데스크톱·모바일 공통 번들을 만들고 Android/iOS assets로 복사했다. 변경된 두 파일×다섯 대상의 SHA **10건**이 일치한다. 새로운 네이티브 바이너리 실행이나 Windows 실행 증거는 아니다.
- 독립 backend/UI 검토 **APPROVE**, 구문·diff 검사 통과. 실제 strict TypeScript/Deno 타입 검사는 수행하지 못했다. 빈 LSP 결과를 대체 증거로 사용하지 않았다.

## 정리와 운영 범위

두 실제 계정을 로그아웃한 뒤 정확한 UUID·이메일·보호 app_metadata 표시자를 확인하고 Admin API로 두 QA 계정만 삭제했다. QA의 **29개 테이블 합계 0**, Auth 사용자/세션 0, Storage 객체 0, Cron 0을 확인했다. 검증용 함수는 **55, 항상 404**로 교체했고 기존 nonce의 wire/cleanup-check/cleanup 요청 세 경로가 모두 404였다. 원문 nonce·비밀번호·쿠키를 담은 로컬 QA 파일도 삭제했다.

원본은 **entities 153, meta 6, Auth mapping 0**으로 유지됐고 여섯 원본 컬렉션 지문 비교가 통과했다. 기존 8787 미리보기는 재시작하지 않았으며 HTTP 200이다. 운영 API의 익명 경계 8건은 통과했지만 **ready:false, setupEnabled:false, publicWebOrigin:null**이다. 첫 검사에서 꺼진 setup flag의 생략을 명시적 false로 기대한 도구 assertion을 수정했으며 제품 소스 변경은 없었다. 실제 소유자 연결·공개 웹 호스팅·운영 전환은 아직 완료하지 않았다.

Supabase 보안 advisor는 ERROR 0, 기존 `extension_in_public` WARN 그룹 1과 `rls_enabled_no_policy` INFO 그룹 1이다. 모든 Notion 유료 기능이 완료되었다고 표시하지 않는다.
