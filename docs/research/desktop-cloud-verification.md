# 데스크톱의 Supabase 직접 연결 검증

2026-10-17 KST. 전체 Notion 기능·5개 플랫폼 전환의 완료 보고가 아니다. 소스 해시, 실행 범위, 패키지 검사와 정리 결과는 [검증 JSON](desktop-cloud-verification.json)에 기록했다.

Supabase 기본 주소를 선택하면 앱에 포함된 공개 화면 14개를 열고, 별도의 창 없는 Chromium 세션으로 고정된 `fountain-api`에 연결한다. 화면에는 Node·preload·인증 쿠키를 제공하지 않는다. 기존 HTTP(S) Fountain 서버 연결도 유지한다. 공개 화면은 `resources/bundle`에 두고 일반 파일·크기·해시를 검증하며, 실행 코드는 ASAR에 보관한다. 설치 앱에 Python 서버나 서버 데이터베이스를 추가하지 않았다.

## 실제 확인한 범위

- 소스 실행과 macOS arm64 설치 앱에서 각각 실제 운영 API의 익명 로그인 화면·서비스 워커·샌드박스·두 번의 시작을 확인했다. 운영 계정 생성이나 원본 데이터 변경은 하지 않았다.
- macOS 설치 앱의 별도 QA 프로필 2개에서 실제 Supabase Auth 로그인, 서로 다른 세션 바인딩, 문서 생성·CRDT 편집·저장·재로딩, 양방향 변경 전달, 앱 재시작 후 같은 서버 재연결, 한 기기만 로그아웃하는 동작을 확인했다.
- 화면의 실제 XHR 업로드로 4,194,421바이트를 Storage의 2개 청크에 저장하고 다운로드 SHA-256 일치를 확인했다. 문서에서 참조하는 첨부 삭제는 실제 API 계약대로 409를 반환했다.
- 이벤트 스트림의 200 연결을 관찰했고 초기 503 뒤 재연결도 있었다. 앱의 SSE·재연결 흐름을 통한 양방향 변경 전달은 확인했으나, 각 변경이 재조회 없이 SSE 프레임만으로 전달됐는지는 분리해 증명하지 않았다.
- 데스크톱 Node 검사 48개, 검증용 Edge 진입점 검사 11개가 통과했다. 기존 서버 연결의 실제 Electron 검사 14개·보안 검사 5개와 실제 Chrome 전송 회귀도 통과했다. Node 문법 검사이며 별도의 TypeScript 타입 검사 증거는 아니다.
- macOS·Windows 패키지의 화면 파일 14개와 실행 파일이 현재 소스와 일치했다. Windows는 x64 PE 파일·번들·해시 검사만 수행했으며 Windows 실행은 미검증이다. 공개 의존성 lock metadata가 포함되는 점도 JSON에 기록했다.

## 인증 검증의 격리 방식

운영 API 9의 원본 작업공간은 유지했다. 검증 도구만 자체 Electron 메인 프로세스에서 고정 API 요청을 nonce로 봉인된 일회용 `fountain-verify` 경로로 전달했다. 이 경로는 실제 애플리케이션과 Auth·PostgreSQL·Storage를 사용하며, 고정된 QA 작업공간·이메일·파일 접두사만 허용했다. 세션 쿠키는 실제 비공개 Chromium 쿠키 저장소에서 설정·전송했고 화면이나 테스트 결과에 값을 내보내지 않았다. 이 요청 경로 변경은 제품 코드의 기능이 아니다.

초기 요청 문제 조사 중 같은 봉인 경로의 실제 애플리케이션으로 QA 소유자 계정을 생성했다. 성공한 UI 검사는 그 서명된 기존 소유자 연결을 이어 사용했다. 따라서 **데스크톱 UI가 신규 공급자 계정을 처음 생성하는 과정**은 이번 성공 증거에 포함하지 않는다. 인증 검사에서는 메인 프로세스의 검증 경로를 먼저 설치하기 위해 설정 화면을 거쳐 재연결했다. 선택 서버의 자동 복원은 별도의 수정 없는 익명 제품 검사에서 확인했다.

## 발견한 문제와 수정

앱이 직접 넣던 `Content-Length`는 Electron의 금지 헤더였다. 실제 Electron 비교에서 헤더를 넣으면 `net::ERR_INVALID_ARGUMENT`, 같은 본문에서 헤더를 빼면 실제 인증 200이 나왔다. 입력 선언 길이·실제 바이트 일치와 10 MB 제한은 유지하고, 전송 길이는 검증한 바이트 버퍼를 바탕으로 Chromium이 계산하게 했다. 회귀 검사 2개가 수정 전 실패하고 수정 후 전체 48개가 통과했다. [Electron 공식 헤더 계약](https://www.electronjs.org/docs/latest/api/client-request#requestsetheadername-value).

기존 4 MiB 조각 업로드는 Electron 내부 버퍼링을 사용한다. 전체 업로드가 처음부터 끝까지 스트리밍된다고 주장하지 않는다. 다운로드는 스트림과 역압력을 유지하며, 헤더 대기 중 화면의 취소가 즉시 전달된다는 주장도 하지 않는다.

## 정리와 남은 범위

테스트를 마친 뒤 보호된 QA 계정 1개와 실제 파일 2개를 API로 삭제했다. QA 29개 테이블의 행·매핑·Auth 세션·Storage 객체·Cron 작업이 0임을 확인했다. 검증 함수는 46의 빈 404 응답으로 교체했으며 이전 nonce의 wire·cleanup 경로 모두 404를 확인했다. 비공개 nonce·비밀번호·임시 세션 입력과 Electron 프로필을 삭제했다.

원본 엔티티 153개·meta 6개와 6개 업무/세션 컬렉션의 지문은 유지됐다. 기존 8787 미리보기는 HTTP 200이며 실제 운영 전환은 하지 않았다. API 9·worker 3·maintenance 3·마이그레이션 25개도 유지했다.

공개 HTTPS 프런트엔드·원본 소유자 계정 연결, iOS·Android 직접 경로의 인증/편집, Windows 실행, 실제 클라우드의 데스크톱 백업·폼/사이트 팝업, 5 GB 전체 전송, 외부 IdP와 원래 유료 기능 전체 대조는 남아 있다. 공개 웹 주소가 없을 때 로컬 `.invalid` 주소의 문서 링크 복사를 비활성화했으며 권한 설정은 유지했다.
