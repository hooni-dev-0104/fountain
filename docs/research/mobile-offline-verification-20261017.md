# 모바일 오프라인 저장 검증

2026-10-17의 격리 검증 기록이다. 모바일 내구성 저장의 배포 플래그는 두 플랫폼 모두 비활성 상태다. 이 문서는 전체 서비스의 운영 전환 완료를 뜻하지 않는다.

## Android

실제 Android SDK·SQLite·WebView에서 복구·본문 변환·권한 검사 35개와 공통 벡터·인증 경계 검사 92개가 모두 통과했다. 두 묶음은 서로 다른 127개 검사이며, 모두 건너뛴 항목이 없다. 대상 앱 APK의 SHA-256은 `a09de3677b1a87a24f43c253bda476c5d888597b53ec10acac332aa45a7451dc`, 테스트 APK는 `bb9411c7e5ba17bd278e636a0e11b1ff7471e0773e875a9e86e675aa15c3b03f`다.

- 서버에서 이미 관찰한 원래 문서의 편집 권한이 사라지면, 편집 가능한 부모를 통해 복제하는 것도 거절한다.
- 영구적인 서버 관찰 표시는 긍정 권한 증거의 용량 한도와 분리한다.
- 내보내기 금지 설정은 소유자에게도 적용하며, 준비 후 설정이 바뀐 경우 기존 내보내기 권한을 무효화한다.
- 전체 본문을 변환할 수 없는 경우 부분 가져오기를 만들지 않는다. 실제 저장소 읽기 실패는 본문 형식 오류로 숨기지 않고 실패로 전달한다.

실제 SDK가 생성한 다섯 합성 본문 결과를 Python 기준 CRDT 구현으로 다시 적용했다. 일반 문자 50,000개, 여러 블록 합계 50,000개, 서식 문자 25,000개, Unicode 보충 문자 50,000개, 기존 처리 작업의 포함 증거 사례에서 전체 본문과 서식이 일치했다. 실제 HTTP 동기화 검증과는 별개다.

실제 Supabase 계정으로 새 로그인을 시도한 경우에는 이전 로그인 범위의 미확정 저널 때문에 초기 검증 단계가 중단됐다. 별도 읽기 전용 SDK 검사에서 두 IndexedDB의 이전 범위 체크포인트 두 개와 미확정 의도 한 개를 확인했다. 이 검사는 외부 요청을 전송하지 않았다. 이전 거래를 새 계정으로 재전송하거나 완료로 판정하지 않고 보존하는 수정은 진행 중이다.

## iOS

동일한 네이티브 제품 코드로 다음 실제 Simulator 검사가 통과했다. 제품 코드의 `App.debug.dylib` SHA-256은 `842e976bb5324c2d3fa1b06abac9bbfe2c1315ea0d237fca8f6219e7f94ac005`다. 캐시 삭제 검사는 실행 코드의 URL 검사 문제를 수정한 별도 테스트 번들을 사용했다.

| 검사 | 확인한 결과 |
| --- | --- |
| 온라인 편집 | 실제 서버 canonical과 네이티브 ACK 저장, 미전송 작업 0개 |
| 오프라인 편집 | 네이티브 SQLite에 미전송 작업 2개 저장 |
| 새 프로세스 재시작 | HTTPS 전송 0건으로 미전송 본문 복원 |
| 브라우저 캐시 삭제 | 기존 IndexedDB 두 개만 삭제·재열거 확인 후, HTTPS 전송 0건으로 본문 복원 |

캐시 삭제 바로 전후 SQLite 여섯 테이블의 논리 데이터 지문, 저장 head, 미전송 작업 수가 동일했다. 다른 DB 개수도 변하지 않았다. 실제 WebView의 persistent data store를 사용했으며 Keychain·기기 설정·네이티브 DB는 삭제하지 않았다.

로그아웃 검사에서는 미전송 작업의 서버 반영과 실제 세션 DELETE 1건까지 확인했다. 이후 익명 세션을 처리하는 과정에서 `OUTBOX_IDENTITY_REQUIRED`가 발생해 로그인 화면 전환이 완료되지 않았다. 따라서 로그아웃 전체 흐름은 통과로 기록하지 않는다.

이전 실행에서 발생한 SQLite 확장 오류 `SQLITE_IOERR_LOCK`의 직접 원인은 확정하지 않았다. Recovery의 불필요한 raw DB 파일 열기·닫기를 SQLite `NOFOLLOW`로 바꾸고 연결 자체의 시스템 오류 진단을 추가했다. 이후의 성공한 실행만으로 이전 오류의 인과적 해결을 주장하지 않는다.

## 보존 범위와 남은 작업

기존 가족 작업공간과 localhost 미리보기는 검증 대상으로 사용하지 않았다. 검증은 별도 작업공간·계정·전용 기기에서 수행했다. 검증용 계정과 임시 함수는 후속 실제 앱 검사에 필요해 아직 유지 중이며, 최종 정리 검증이 남아 있다.

새 로그인 저널 보존, 익명 세션 전환, 양 플랫폼의 최종 앱 실행 및 독립 검토를 마친 뒤에만 배포 플래그 활성화를 판단한다. AI·배포·다른 플랫폼의 완료 여부는 이 검사로 증명하지 않는다.
